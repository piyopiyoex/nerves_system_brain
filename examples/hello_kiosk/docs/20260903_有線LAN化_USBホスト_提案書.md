# USB-Ethernet アダプタによる有線 LAN 化 提案書

- 日付: 2026-09-03
- プロジェクト: hello_kiosk_brain / nerves_system_brain（PW-SH6）
- 目的: [nerves_system_atomcam2](https://github.com/piyopiyoex/nerves_system_atomcam2)
  と同じ方式（**USB-Ethernet 変換アダプタ + VintageNet**）で PW-SH6 を有線 LAN に接続する
- 位置づけ: これまでの USB-NCM ガジェット（母艦との 1:1 リンク）を、
  **通常の LAN 接続**に置き換える。crng/OTA/USB 停止で悩んでいた諸課題を構造的に解消しうる

---

## 1. AtomCam2 方式の要点（調査結果）

AtomCam2（Ingenic T31, DWC2 USB）は、**USB ホストポートに USB-Ethernet アダプタを挿し、
VintageNet で有線 LAN として使う**方式。カーネル config（linux-3.10.14.defconfig）で
以下のドライバを **=m（モジュール）** で有効化している:

```
CONFIG_USB_USBNET=m
CONFIG_USB_NET_AX8817X=m        # ASIX AX88172/8772 系
CONFIG_USB_NET_AX88179_178A=m   # ASIX Gigabit 系
CONFIG_USB_NET_CDCETHER=m       # CDC Ethernet
CONFIG_USB_NET_RNDIS_HOST=m
CONFIG_USB_RTL8152=m            # Realtek RTL8152/8153（AtomCam2 純正 LAN アダプタ）
CONFIG_USB_DWC2_HOST_ONLY=y     # USB をホスト専用に
```

ネットワークは **VintageNet + vintage_net_ethernet**（Nerves 公式）で `eth0` を管理。
Wi-Fi(WPA_supplicant)、USB 有線 LAN、mDNS を併用。

## 2. PW-SH6 への適用可否（決定的な確認事項）

### 2.1 ハードウェア: USB をホストにできるか【要実機確認】

- i.MX28 の USB は **ChipIdea(ci_hdrc) コントローラ**で、**OTG（ホスト/デバイス両対応）**。
  実際、配布イメージのオリジナル DTB は `dr_mode = "host"`、Brainux は `peripheral` に
  変更して使っていた（＝**ホストにもできる**ことがハード的に確定している）
- **本提案は DTB を再び `host` に戻し、USB-Ethernet アダプタを挿す**方向
  （今日 gadget のために `peripheral` 化したのと逆）
- **未確認**: PW-SH6 の microUSB ポートが物理的に USB ホスト給電・OTG を通すか
  （電子辞書の端子は PC 接続前提の可能性。OTG ケーブル/セルフパワー Hub が要るかも）

### 2.2 カーネル: USB Ethernet ドライバがあるか【要確認】

- brain-hackers の linux-brain（Linux 6.1）に上記ドライバが含まれるか。
  含まれなければ**カーネル再ビルドで有効化**が必要（config 変更のみ、コードは不要）
- モノリシックカーネル（/lib/modules 無し）のため、**=m ではなく =y で組み込む**必要がある
  （AtomCam2 は =m だが本機はモジュールロード機構が無いため）

### 2.3 電源・OTG 配線: 本方式の【最大リスク】

**「i.MX28 が USB Host 対応」≠「PW-SH6 の microUSB 端子が実際に Host として使える」**。
最大の未知数は Linux の Host 機能ではなく、**PW-SH6 実機の USB 電源・OTG 配線**:

- microUSB の **VBUS（5V 給電）/ OTG ID ピン**がどう実装されているか
  （電子辞書の端子は PC 接続=デバイス側前提で、VBUS 出力や ID 検出を持たない可能性）
- USB ホストはアダプタへ 5V 給電が要る。i.MX28 の VBUS 供給能力・PW-SH6 の回路次第で、
  **セルフパワー USB Hub や Y字ケーブルでの外部給電が現実解**（むしろ前提と考える）
- i.MX28 の host DTB では `vbus-supply` を明示する構成が一般的。この供給元が
  PW-SH6 で機能するかが鍵

## 3. この方式が解決する課題（大きな利点）

**重要**: 有線 LAN 化は「ネットワーク到達経路」の問題を解くもので、**crng（乱数）問題とは
別問題**。両者を切り離して扱う。

```
              ┌─ USB-NCM 依存 / 母艦 1:1 制約  → USB Ethernet 化で解消
PW-SH6 の課題 ┤
              └─ crng 未初期化で SSH 起動待ち   → persistent seed 等で別途対策（未解決のまま）
```

| これまでの課題 | 有線 LAN 化で | 備考 |
|---|---|---|
| USB-NCM は母艦との 1:1、他機器と通信不可 | **解消** — 通常の LAN に参加 | |
| 母艦を常に繋ぐ必要 | **解消** — LAN 上のどこからでも到達 | |
| USB ガジェット常時接続の是非（前提案書） | **論点が消える** — LAN 常時接続＝正常運用 | |
| SSH の到達経路 | **大幅改善** — LAN 経由で到達 | 到達性の話 |
| OTA 経路が USB のみ | **LAN 経由 OTA 可能**（NervesHubLink 含む） | |
| **crng 問題そのもの** | **未解決** | LAN 化と無関係 |
| **SSH 起動時の crng 待ち** | **残る可能性あり** | ホスト鍵は事前生成済みだが、接続毎の乱数取得で待つ場合あり。別途 persistent seed で根治 |

つまり有線 LAN 化は **USB-NCM / 母艦依存 / USB 停止論を構造的に解消**するが、
**crng 問題は独立に残る**。両者を混同しない。

## 4. 実装方針

### 4.1 ハードウェア構成

```
PW-SH6 microUSB ──(OTG/ホスト化)── USB-Ethernet アダプタ ── LAN
                                    (推奨: RTL8152 or AX88772、Linux 定番)
        └── 給電が別途要るなら セルフパワー Hub / Y字ケーブル
```

アダプタは **RTL8152（AtomCam2 純正と同じ）か ASIX AX88772** を推奨（Linux で枯れている）。

### 4.2 ソフトウェア（nerves_system_brain 変更）

1. **DTB**: `usb@80080000` を `dr_mode = "host"` に（配布オリジナルがこれ。
   gadget 用の peripheral パッチを外す or host 版 DTB を用意）
2. **カーネル config**（linux-brain 再ビルド）:
   `USB_USBNET / USB_RTL8152 / USB_NET_AX8817X / USB_NET_CDCETHER`、USB ホスト（ci_hdrc host 有効）。
   現行 nerves_system_brain は /lib/modules を使わない構成のため、これらは **=y で組み込む**
   （カーネルがモジュール非対応という意味ではなく、モジュールロード機構を持たない現構成での簡便策。
   `CONFIG_MODULES` の状態を確認のうえ =y 化）
3. **Buildroot**: `vintage_net` + `vintage_net_ethernet` を追加（AtomCam2 同様）
4. **アプリ(hello_kiosk_brain)**: ネットワークを VintageNet 管理に。
   **インターフェース名は決め打ちしない** — Phase 0 で実際の名前（`eth0`/`eth1` 等）を確認し、
   VintageNet では `hw_path` ベースの固定名（例 `lan0`）も検討。DHCP 構成。
   右上 IP 表示はその実インターフェースの IP に。gadget 起動スクリプトは撤去

### 4.3 カーネル再ビルドについて

これまで「brain-hackers カーネルを固定流用（再ビルド回避）」方針だったが、
USB Ethernet ドライバ組み込みには **linux-brain の再ビルドが不可避**。
config 変更のみ（ソース改変なし）なので、pin したコミットに対する defconfig 差分で管理する。
これは前 OTA 提案書の「U-Boot 改造」よりリスクは低い（カーネル config は差分が明確）。

## 5. 段階計画

### Phase 0（最重要の分岐点）: Brainux 上で USB Host + USB Ethernet を実証

**Nerves を一切いじらず、既に SSH が動く Brainux + 実験用 host DTB で**段階検証する。
最大リスクは Linux の USB Host 機能ではなく、**PW-SH6 実機の USB 電源(VBUS)・OTG 配線**。

| 段 | 内容 | 確認 | 完了条件 |
|---|---|---|---|
| 0-A | USB Host 自体。OTG ケーブル+給電で **USB メモリ**等を挿す | `dmesg` / `lsusb` | 単純 USB デバイスを認識 |
| 0-B | USB-Ethernet アダプタを挿す（DHCP 不要） | `dmesg`（`r8152`/`ax88…`）/ `ip link` | NIC が Linux に認識・インターフェース生成 |
| 0-C | LAN に接続 | `udhcpc` / `ip addr` / `ping router` / `ping PC` | DHCP で IP 取得、LAN 内疎通 |
| 0-D | LAN 内 PC から SSH | `ssh user@<IP>` | LAN 経由ログイン成功 |

**成功判定チェックリスト**（G/H/I の再現性が Nerves 化には必須）:

| # | 判定 | 重要度 |
|---|---|---|
| A | USB Host としてデバイスを認識 | 前提 |
| B | USB Ethernet NIC を認識 | 前提 |
| C | Ethernet インターフェース生成（実名を記録） | 前提 |
| D | DHCP で IP 取得 | 必須 |
| E | LAN 内 PC から ping | 必須 |
| F | LAN 内 PC から SSH | 必須 |
| G | **再起動後も自動認識** | 高 |
| H | **USB 抜き差し後も復旧** | 高 |
| I | **Ethernet リンク断→復旧** | 高 |
| J | SSH 起動時の crng 待ちの有無を別途測定 | 参考（crng は別問題） |

**Phase 0 の戻れる設計**: 実験用は **別の SD / 別 DTB**（host 版）で行い、通常運用の
Brainux SD（peripheral / USB-NCM）は温存する。host 化すると USB-NCM は使えなくなるため。

### Phase 1 以降

| Phase | 内容 | 完了条件 |
|---|---|---|
| **1. カーネル config** | linux-brain に USB Ethernet ドライバ(=y)を追加してビルド、Brainux で動作確認 | 再ビルドカーネルで NIC 動作 |
| **2. Nerves 統合** | nerves_system_brain に host DTB + 新カーネル + vintage_net_ethernet を統合 | Nerves 起動で NIC が VintageNet 管理下に |
| **3. アプリ移行** | hello_kiosk_brain を有線 LAN 前提に（gadget 撤去、IP 表示、SSH は LAN 経由） | LAN 上から SSH/配備、KIOSK が LAN IP 表示 |
| **4. OTA(任意)** | LAN 経由で NervesHubLink or ssh_subsystem_fwup | 無線更新 |

Phase 0 が通らなければ（microUSB がホスト+給電を通さない）ハード的に本方式は不可
→ **USB-NCM を継続**（保険として残す）。

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **microUSB がホスト給電を通さない** | 本方式が不成立 | Phase 0 で最優先確認。セルフパワー Hub / Y字給電を用意。ダメなら USB-NCM 継続 |
| linux-brain にドライバが無い | 再ビルド必須 | config に =y 追加（コード改変なし）。pin コミット + defconfig 差分で管理 |
| モノリシックで =m 不可 | モジュールロード不可 | 全て =y で組み込む |
| VBUS 供給不足でアダプタ不安定 | リンク断続 | 外部給電（セルフパワー Hub）必須と想定 |
| 有線 LAN 化で USB-NCM 開発手段を失う | 移行期の開発性低下 | Phase 3 まで USB-NCM 版 SD を温存（並行運用） |
| crng(SSH) 課題 | 残存 | LAN 経由なら mDNS/NervesHub 等で回避余地。別途 persistent seed で根治 |

## 7. ネットワーク方針（第一候補 / 保険）

有線 LAN を第一候補、USB-NCM を開発・復旧用の保険として**両方残す**:

```
                 ┌─ USB Ethernet ──→ 第一候補（通常運用）
PW-SH6 Network ──┤
                 └─ USB-NCM ───────→ 開発・復旧用バックアップ
```

Phase 0〜2 では両立させ、有線 LAN が **G/H/I（再起動・抜き差し・リンク断からの復旧）**まで
安定して初めて通常運用を有線に移す。RTL8152 が特定 Hub で不安定等が起きても振り出しに
戻らない。

## 8. まとめ / 次アクション

- AtomCam2 と同じ **USB-Ethernet アダプタ + VintageNet** 方式は、i.MX28 が USB ホスト
  （OTG）対応であることから **PW-SH6 でも成立の見込み**。成立すれば USB-NCM / 母艦依存 /
  USB 停止論を構造的に解消できる（**crng 問題は別問題として残る**）
- 成否は **Phase 0（microUSB が USB Host+給電を通すか＝VBUS/OTG 配線）** の実機検証にかかる。
  最初に、しかも**既に SSH が動く Brainux + 実験用 host DTB（別 SD）で**確認するのが
  最短・低リスク（Nerves 側をいじる前にハード可否を確定でき、通常運用 SD も温存できる）
- 前 OTA 提案書（USB-NCM 前提の OTA / USB 停止）は、**USB-NCM 依存部分が見直し対象**になる。
  ただし crng / SSH / fwup / NervesHubLink はそれぞれ独立課題であり、有線 LAN 化で
  自動的に解決するわけではない
