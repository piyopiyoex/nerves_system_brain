## 2. 本日の確定事実（実機で検証済み・信頼してよい）

### 2-1. SSH が遅い真因（★重要な発見）
- **原因は crng そのものではなく、persistent random seed の欠如**だった。
- Brainux が起動直後に SSH 可能なのは **`systemd-random-seed.service`** が
  前回シード（`/var/lib/systemd/random-seed`）を crng に投入して即初期化するため。
  Brainux は rngd/haveged なし、hwrng なし（`rng_current=none`）。
- Nerves にはこの一手が無く、crng をゼロから貯めて **160〜250秒**待っていた。
- **対策の効果を実証**: Nerves に seed 投入（RngSeed + rngseed ヘルパー、
  systemd と同じ RNDADDENTROPY で credit）を入れたところ、
  **`random: crng init done` が起動後 13.16秒に短縮**（dmesg で確認）。
  → seed 方式は正しく効く。SSH は「使いものにならない」のではなく、この一手が
  欠けていただけ。**当初の「crng の人質」という私の説明は誤り。**

### 2-2. 音（SGTL5000）が鳴らない真因
- DTB のコーデック/SAIF/pinctrl/電源は **EVK 標準通りで正しい**（精査済み）。
- 実機レジスタも正常: DIGCTL SAIF_CLKMUX_SEL=2(EXTMSTR0)、SAIF0 RUN=1、
  クロックゲート開。pinmux も MCLK/LRCLK/BITCLK/SDATA0 が正しく割当。
- それでも **SGTL5000 が I2C 応答しない（ENXIO）**。i2cprobe で直接確認。
- i.MX28 既知問題: SGTL5000 は MCLK が無いと I2C にすら応答しない。原因は
  カーネルの MCLK 供給タイミング（mxs-saif が EXTMSTR で probe 時に MCLK 未出力）
  と推定。**ソフト（レジスタ/再バインド）では復活できず、カーネル再ビルドが必要**
  と判断した段階で中断。

### 2-3. PWM ブザーの発見（★音の別ルート）
- DTB 末尾に **`buzzer { compatible = "pwm-beeper"; status = "disabled"; }`** と
  **`buzzer_cold`（アンプ電源, disabled）** を発見。
- **SGTL5000 の MCLK 問題を回避して、BEEP 音だけなら PWM ブザーで鳴らせる可能性**。
  DTB で status を okay 化 + pwm-beeper ドライバ確認（カーネル）が必要。未検証。

### 2-4. 電源 OFF の仕組み
- DTB の `poweroff`（syscon-poweroff, HW_POWER offset 0x104 に 0x3e770001）で
  **ソフトからの物理電源断が可能**（`poweroff` 相当）。電源 ON はハード/ブートローダ管轄。

### 2-5. その他ハード事実
- タッチ: `/dev/input/event1`（mxs-lradc-ts）、ABS_X/Y 0..4095。
- キーボード: `/dev/input/event0`（brain-kbd-gpio）。
- バッテリー: i.MX28 HW_POWER の HW_POWER_STS(0x800440C0=5V検出) /
  HW_POWER_BATTMONITOR(0x80044054=BATT_VAL, 8mV/LSB)。**レジスタ定義は文献通りだが
  実機の実値検証は未**。
- DTB は USB を `dr_mode="peripheral"`（ガジェット）に設定済み。有線 LAN 化には
  `host` へ戻す必要（別提案書）。

## 5. 明日の進め方（推奨順・証拠ドリブン）

### 最優先: SSH を「速く・確実」にする（他の全作業の土台）
seed 方式は crng を 250→13秒に縮めた実績がある。これを**確実にクラッシュしない形**で
入れ直す。**手順（1変更ずつ・証拠を取りながら）**:
1. 原点（Display+SshDaemon, UP進む）から出発。
2. **RngSeed だけ**を足してビルド・配備・リセット。
3. `#` クラッシュしたら → **SD で crash_dump の Slogan を必ず読む**（推測しない）。
   → RngSeed.init の例外か System.cmd 失敗かを Slogan で確定 → 直す。
4. RngSeed が安定して crng が速くなった（dmesg で確認）ら、SSH 開通時間を実測。
5. さらに速くするなら seed 投入を erlinit の pre-run（BEAM 起動前）へ移す検討。

### 次: KIOSK デモ復元（SSH が速くなってから）
SSH が快適になれば、以降は**ホットリロードで安全に1モジュールずつ**検証できる。
1. Battery だけを足して `:sys.get_state(Battery)` で動作確認（実値検証も）。
2. Input だけを足して evdev イベントが届くか確認。
3. Kiosk を足す。**UP が止まったら即 `:sys.get_state(Kiosk)` と crash_dump を見る**
   （今日はこれをやらずに推測して失敗した）。

### 中期: 音（PWM ブザー）
- DTB で `buzzer`/`buzzer_cold` を status=okay 化 + pwm-beeper ドライバ確認。
  SGTL5000 の MCLK 問題を回避して BEEP を狙う。カーネル/DTB 再ビルドを伴う。
- SGTL5000 本格復活は MCLK タイミング修正（mxs-saif）で、より重い。

### 中期: 有線 LAN 化（機材が揃ったら）
- USB-Ethernet アダプタ（RTL8152/AX88772）+ OTG + セルフパワー Hub。
- 手順書（Phase0）に従い、**Brainux + host DTB** でハード可否から確認。
