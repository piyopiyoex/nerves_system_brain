## 1. 次にやること(推奨)= 予備機到着後の USB ホスト化

**最優先タスクは、予備機(調達中の新古品)到着後の「USB ホスト化」**。これが音声と
有線 LAN の両方を一気に解決する共通基盤になる。

### なぜ USB ホスト化が本命か
- **音声**: オンボード codec(SGTL5000@0x0a 不在・0x1a 同定不能)は回路情報の壁で凍結。
  実機カーネルに `CONFIG_SND_USB_AUDIO=y` / `CONFIG_USB_CHIPIDEA_HOST=y` が**既に組込済**
  (/proc/config.gz で確認)。→ USB オーディオはカーネル再ビルド不要でコーデック同定の
  壁を丸ごと迂回できる。
- **有線 LAN**: USB-Ethernet + VintageNet(docs/20260903_有線LAN化_USBホスト_提案書.md)。
- **給電**: セルフパワー Hub 経由。PC USB では放電するため(§0-5)、Hub 給電が必須級。
- ホスト + セルフパワー Hub なら **USB-Ethernet(LAN+開発アクセス)+ USB オーディオ を
  同時接続**でき、1つの Hub で「LAN + 音声 + 給電」が揃う。

### 分岐点 = Phase 0(ハード)
- i.MX28 は OTG 対応で Linux ホスト化は可能。だが **PW-SH6 の microUSB 端子が
  「ホスト給電(VBUS)+ OTG」を物理的に通すか**が未確認。通らなければ USB 経路全体が不成立。
- 現状は USB gadget(USB-NCM, ci_hdrc.0 peripheral)。host 化には DTB の dr_mode 変更が要る。
- 手順: docs/20260903_Phase0_USBホスト有線LAN_実機検証手順書.md に沿って 0-A(USBメモリ認識で
  VBUS/OTG 可否確認)→ 0-B/C/D。**別 SD の host DTB で実験し、通常運用 SD(NCM)は温存**。
- 電源トポロジー注意: ホストモードでは Brain が VBUS を「供給する側」。同ポートからの充電は
  通常不可。セルフパワー Hub が Brain 側へ 5V 逆流給電する "OTG給電対応" タイプが必要。
  i.MX28 は「5V が来れば起動」性質があるので逆流給電型なら給電/充電しうる → **Phase0 で
  電池ログ(§0-5)を見て mv 上昇=充電 / 横ばい=給電のみ / 低下=給電なし を判定**。

### 準備しておく機材(到着待ちの間に確保可)
- USB-Ethernet アダプタ(RTL8152/8153 か ASIX AX88772/88179、Linux で枯れている)
- USB オーディオドングル(UAC1/UAC2 標準クラス)
- microUSB OTG ケーブル(ID 結線)
- **セルフパワー USB Hub(OTG 給電対応/ホストへ逆流給電するタイプ)** ← 重要

### USB オーディオ再生の細部(Phase0 通過後)
- ドングルを挿すと `/proc/asound/cards` に USB サウンドカード出現。
- 8kHz/mono/16bit WAV から再生テスト。`aplay`(alsa-utils)は Nerves 未収録の可能性 →
  buildroot に `alsa-utils` 追加(軽量な system 再ビルド)か、Elixir から
  `/dev/snd/pcmC*D*p` へ PCM 直書き。素材は hello_kiosk_papapa/priv/audio/notes 流用可。

## 2. 凍結・打切り中の課題(回路情報待ち)

| 課題 | 状態 | 再開の入口 |
|---|---|---|
| バックライト独立制御 | 不可(LCD 一体)と確定 | DRM 正規 disable 経路(Sleep In/Display On)実装。重い |
| オンボード音声 codec 同定(0x1a) | ソフト同定は限界 | ロジアナ or **基板目視で 0x1a の IC 型番確認** |
| PWM ブザー(タッチ音) | pinmux 再現でも無音 | 回路情報 or USB/コーデック経由 |

これら3つ(バックライト実配線・0x1a・ブザー)は**全て「PW-SH6 の回路情報が無い」同じ壁**。
基板目視や brain-hackers 情報が最短の突破口。

## 3. 実機・運用メモ(重要)

- **接続**: `ssh user@10.42.0.2`(母艦 10.42.0.1 ⇔ Brain 10.42.0.2、USB-NCM)。鍵認証・
  BatchMode 可、シェルは Elixir exec。まず `ping 10.42.0.2` で疎通確認。
- **SSH シェルは Elixir**: リモートコマンドは Elixir 式で書く。**日本語をコメントに書くと
  パーサが壊れる**ことがある(`` 等)。日本語は文字列リテラル内のみ、コメントは ASCII。
- **配備(ホットリロード。再起動不要)**: `./scripts/build_release.sh` →
  sftp で beam を `/srv/erlang/lib/hello_kiosk_brain-0.1.0/ebin/` へ put →
  `:code.get_object_code` + `:code.load_binary` + 必要なら `GenServer.stop`(スーパーバイザ再起動)。
  **配備検証は md5 照合を徹底**(SSH 不安定で sftp が無言失敗することがある。今回1度発生)。
  scp は `-O`(旧プロトコル)だと Elixir exec シェルと非互換で失敗 → **sftp を使う**。
- **NIF .so の手動ビルド**: `MIX_APP_PATH=_build/prod/lib/hello_kiosk_brain
  ERTS_INCLUDE_DIR=<staging>/erts-*/include make CXX=<...>/o/host/bin/arm-linux-g++`
  (make 既定 g++ がホスト用になるため CXX 明示)。build_release だけだと .so が
  再コンパイルされないことがある。
- **RTC 無し** → 再起動毎に `./scripts/settime.sh`。
- **ホスト鍵**: 実機再書き込み等で変わると弾かれる。`ssh-keygen -R 10.42.0.2` で更新。
- **カーネルは Brainux 流用**: nerves_system_brain は独自カーネルをビルドせず
  brain-hackers linux-brain の zImage/DTB をそのまま使う(モノリシック、/lib/modules 無し→
  ドライバ追加は =y)。DTB 差替えは SD p1(FAT boot)=物理 SD 往復。
- **linux-brain ソース**: /home/owner/my_nerves_examples/linux-brain(DTS/ドライバ精査に有用)。
  PW-SH6 固有: arch/arm/boot/dts/imx28-pwsh6.dts、共通: imx28-brain.dtsi。
- **実機ヘルパー**(/root、src/ にソース): `/root/devmem`(mmap read/write)、`/root/i2cack`、
  `/root/i2cread`。Nerves の /tmp は noexec。
