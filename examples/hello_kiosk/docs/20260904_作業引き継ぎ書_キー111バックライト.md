## 0. 最優先の未解決課題：キーコード111でバックライトON/OFFが効かない

### やりたいこと
物理キー **コード111** を1回押す → LCD バックライトがトグル（点灯↔消灯）。

### 実装済み（未コミット：`lib/hello_kiosk_brain/kiosk.ex`）
`handle_info({:key, 111, :down}, st)` を追加し、**デバウンス**（直近500ms内の111は無視）
してトグル。消灯中(asleep)→wake（点灯）、点灯中→backlight_sleep（消灯）。
state に `last_bl_toggle: 0` を追加。`defp backlight_sleep/1`（Backlight.off + asleep=true）。

### 判明していること（実機実測）
- **物理111を1回押すと `v=1`(押下)/`v=0`(離す) のみ**。バウンスもオートリピートも無い
  （クリーン）。→ 1押下 = `{:key,111,:down}` 1回。
- **シミュレート `send(kiosk,{:key,111,:down})` はトグル成功**（brightness 7→0, asleep=true）。
- **Input.sub = Kiosk（購読は正常, sub_ok=true）**、Kiosk は物理キーを受信している
  （KEYSタブで111が表示されない＝111ハンドラが横取り＝受信の証拠）。
- なのに **ユーザーが物理111を押すとバックライトが変化しない**（何度か再現）。
  ※ 一度だけ monitor で 7→0 を捕捉した回もあり、挙動が不安定。

### 未完了の切り分け（次にやること）
最後にここで中断: baseline を記録（`last_bl_toggle=734417, asleep=false, bl=7`）→
ユーザーが111を押した → **押下後の `last_bl_toggle` を読む前に暴走で中断**。
- **次の一手**: 物理111押下の前後で `:sys.get_state(Kiosk).last_bl_toggle` を比較。
  - 変化した = ハンドラは発火している → バックライト適用側 or 直後に別入力で戻っている
    （touch ノイズで wake、偶数トグル等）を疑う。
  - 変化しない = 111 :down がハンドラに届いていない → 経路/リーダ/購読を疑う。
- **ホットリロードを重ねて状態が濁っている疑いが濃厚**。`kiosk.ex` を確定させたら
  **クリーンに再起動**（/srv/erlang の確定版で起動）してから物理テストするのが確実。
- 設計が複雑（asleep と backlight の結合 + デバウンス）。**うまくいかないなら、111 を
  「現在の brightness を読んで 0↔7 を反転するだけの純粋トグル」に単純化**する案が有力
  （asleep 状態機械と切り離す）。

### 注意（ハマりどころ）
- **Input を GenServer.stop で再起動すると Kiosk の購読が切れる**（Input.init は sub=nil、
  Kiosk が init で購読する設計）。Input を単独リロードしたら
  `HelloKioskBrain.Input.subscribe(Process.whereis(HelloKioskBrain.Kiosk))` で再購読が必要。
  → 基本は Kiosk 側だけ触り、Input を触ったら再起動 or 再購読すること。
- 診断中の一時描画（`Native.render` でテスト文字）を残すと、スリープで凍結して
  「画面異常」に見える。テスト描画後は必ず paint で復帰させる。

## 1. このセッションで完了・コミット済みの作業

- **電源OFFロジック確定**（コミット 495b02c/805a9a5/d6ee0fa/fd9d937）:
  - USB/充電器(5V)接続中に「切る」→ i.MX28 は電源断できず**再起動**になる（実機確認）。
  - 5V検出は **UDC state**（`/sys/class/udc/*/state` != "not attached"）ベース。
    HW_POWER bit29(VDD5V_GT_VDDIO)は電池~3.7V>VDDIO 3.3Vで**常に1になり使えない**。
  - 5V検出時は poweroff せず `:needs_unplug` 案内（戻る付き）を出す。電池駆動時のみ poweroff。
  - `/sbin/poweroff` は**非同期で即戻る**（成否を戻り値で判定不可）。
- **NIF .so を 44MB→2.66MB に削減**（コミット 5661caa/61e4602）:
  - Makefile に `-ffunction-sections -fdata-sections -Wl,--gc-sections -s` 追加。
    未使用 efont(ja/cn/kr/tw)が gc されて激減。IPA フォントは保持、日本語描画OK。
  - **SD読取り 3456ms→324ms** に短縮。ただし **起動時タッチ遅延は改善せず**（後述）。
- **Input オートリピート分離**（コミット 92f2b9a）: evdev val=2 を `:repeat` にして
  `:down` と区別（購読側は :down のみ処理）。

## 2. 起動時タッチ遅延（別の未解決課題・保留）

- 症状: 起動直後 5〜15秒、タッチ反応が遅延。
- **NIFサイズ(44MB)が原因という仮説は外れた**（.so縮小しても改善せず）。
- 未特定。SSH経由の計測は crng(SSH起動~十数秒)を含むため不適。タッチ/UIはSSHより前に立つ。
- 次: Input に heartbeat + reader trace を仕込んで（前セッションで作りかけ→revert済み）、
  再起動+ユーザー物理タッチで `/tmp/input_trace` を取り、リーダの open/read 時刻と
  スケジューラ飢餓の窓を可視化して一発特定する。詳細:
  [20260904_起動時タッチ遅延_調査.md](20260904_起動時タッチ遅延_調査.md)。

## 4. 実機・運用メモ

- SSH: `ssh user@10.42.0.2`。母艦 10.42.0.1 ⇔ Brain 10.42.0.2（USB-NCM）。
  **接続が断続的に不安定**（多段コマンドが 255 で落ちる）。結果はファイル経由で読むと安定。
- ビルド/配備: `./scripts/build_release.sh` → beam を sftp で
  `/srv/erlang/lib/hello_kiosk_brain-0.1.0/ebin/` へ put → `:code.load_binary` + `GenServer.stop`。
  .so は `/srv/erlang/lib/hello_kiosk_brain-0.1.0/priv/kiosk_nif.so`。
- RTC 無し → ブート毎に `./scripts/settime.sh`。
- 電池切れに注意（PC USB は給電のみで充電不可、純正充電器で充電）。
- 手動 make は `make CXX=<toolchain>/bin/arm-linux-g++`（make既定の g++ が `?=` を上書きするため）。
