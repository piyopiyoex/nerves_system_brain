## 3. 作業経過

### 3.1 Phase 0: 起動確認と接続確立（2026-08-31〜09-01）

1. **Brainux 起動確認**: buildbrain イメージを microSD に書き込み、実機起動を確認
2. **RAM 実測**: `free -m` → total 112 / used 59 / available 52MB。
   Debian 常駐分が 59MB を占め、Nerves 化でこれが消える価値を定量確認
3. **直接 SD ブート**: `nk` ディレクトリ方式で成功。起動経路が確定し、
   ファームウェア Ver.3.7 以降の非公式アプリ起動保護は運用上無関係となった
4. **USB-NCM 開通まで**（詳細は接続手順書）:
   - 旧イメージでは `/sys/class/udc/` が空で不動作 → **NCM 対応（2026-03-25 リリース系）
     イメージへ書き直し**が必要だった
   - さらに **`sudo brain-config` でのガジェット有効化**が必要（raspi-config 相当）
   - IPv4 手動設定（10.42.0.x、「7」キーバグ回避の採番）で ping → SSH 成功
   - 実機カーネル: Linux 6.1.70 armv5tejl（2026-03-24 ビルド）

### 3.2 Phase 1-A: OTP/Elixir の成立確認（2026-09-02）

1. 母艦 NAT（ip_forward + MASQUERADE）で Brain を外部接続し `apt` を使用
2. `apt update` が素の 128MB では **OOM で Killed** → 一時 swapfile 256MB（`/swap`）で解決
3. `erlang-base` インストール → **OTP 27.3.4.1** が動作
   - BEAM 1個の RSS: **約 20〜23MB**（見積り 25〜40MB の下限側）
   - `erlang:memory(total)`: 16.3MB
   - 誤って BEAM 3個同時起動になった際も swap 併用で稼働（副次的ストレス実験）
4. `elixir` インストール → **Elixir 1.18.3 on OTP 27** を確認

### 3.3 Phase 1-B: フレームバッファ描画の実用性確認（2026-09-02）

1. `/sys/class/graphics/fb0/virtual_size` = **854,480** を確認
2. `cat /dev/urandom > /dev/fb0` で画面ノイズ、`/dev/zero` で黒クリア → 書き込み経路確認
3. Elixir 生成データ（`<<0x00, 0xF8>>` × 854×240）の描画で**上半分が赤** →
   **RGB565 リトルエンディアン・16bpp・ストライド 1708B（パディングなし）で確定**
4. `:file.write` による Elixir 直接描画を赤→青（`<<0x1F, 0x00>>`）切り替えで確認
5. GenServer + `Process.send_after`（1秒周期）+ `:file.pwrite` で帯の色替えを継続駆動
6. swap を外した状態（available 51MB）でも Elixir 起動を確認（mem 18.4MB）

## 4. 確定した実装仕様（Phase 3〜4 への引き継ぎ）

```
── 起動 ──
起動経路   : 直接 SD ブート（nk ディレクトリ内容をブートパーティション直下へ）
ベース資産 : buildbrain 2026-03-25 リリース系（Linux 6.1.70 / Debian 13.4 / USB NCM）

── ネットワーク ──
方式       : USB-NCM（要 brain-config 有効化。Nerves では同等の configfs 構成を再現）
アドレス   : Brain 10.42.0.2/24 ⇔ 母艦 10.42.0.1/24（「7」を含まない採番）

── 描画（Brain バックエンドの正解パラメータ）──
デバイス   : /dev/fb0（854×480, 16bpp RGB565 リトルエンディアン, ストライド 1708B）
API        : :file.open("/dev/fb0", [:write, :raw, :binary]) + :file.write / :file.pwrite
色の例     : 赤 <<0x00,0xF8>> / 青 <<0x1F,0x00>>
禁止事項   : :raw ハンドルへの IO.binwrite（エラーなく不発になる）

── バージョン固定 ──
OTP        : 27 系（Debian trixie armel: 27.3.4.1 で実績）
Elixir     : 1.18 系（1.18.3 で実績）
```

## 5. 得られた教訓・既知の問題

| # | 事象 | 教訓・対策 |
|---|---|---|
| 1 | 旧イメージで USB ガジェット不動作（`/sys/class/udc/` 空） | NCM 対応イメージ（2026-03-25〜）が必須。`brainux_version` ファイルの有無で新旧判別可 |
| 2 | イメージ更新だけでは NCM が有効にならない | **`sudo brain-config` での有効化が必要**。Nerves 化時は brain-config 相当の configfs 構成を rootfs 起動処理に組み込む |
| 3 | Brain キーボードで「7」が入力不能（既知バグ） | 本体で直接入力する文字列（IP 等）には 7 を含めない。Nerves 化時の evdev キーマップで要検証 |
| 4 | `apt update` が OOM で Killed | 128MB では Debian のパッケージリスト解析すら厳しい。一時 swapfile で回避。**Nerves 化で Debian 常駐を消す価値の実証** |
| 5 | `:raw` ファイルへの `IO.binwrite` が不発（エラーなし） | fb 書き込みは必ず `:file.write` / `:file.pwrite` を使う。「done が出たのに描画されない」場合はまずこれを疑う |
| 6 | IP 設定・NAT 設定は揮発性 | Brain 再起動・ケーブル抜き差しで消える。毎回の再設定手順は接続手順書 §5、恒久化は §6 |
| 7 | 母艦と Brain のコマンド実行先の混同事故 | プロンプト（`owner@localhost` vs `user@brain`）で必ず確認。復旧手順は接続手順書 §7.4 |
| 8 | 検証テストで直前と同じ色を書いて「変化なし」と誤判定しかけた | 状態変化を伴うテストは必ず**前と異なる値**で行う（赤→青切り替えで確定させた） |

## 6. 計画への影響

- 提案書 §3 の OTP 候補表は**候補 A（OTP 27 + Elixir 1.18）で確定**。OTP を古い版に
  落とすシナリオ、および案C（AtomVM への切替）の保険は不要となった
- Phase 2（ツールチェーン自作）のターゲットは **glibc / OTP 27 / Elixir 1.18** に固定
  （Debian armel が glibc で動作している実績に合わせる）
- BEAM 実測 RSS 約21MB により、Nerves 化後（Debian 常駐約60MB が消える）は
  アプリ込みでも余裕を持って 128MB に収まる見通し
- swap なし起動の確認により、Nerves 標準の swap なし運用に問題なし

## 7. 次のアクション（Phase 2: armv5tej soft-float ツールチェーン自作）

母艦での作業が中心。実機は一旦シャットダウンして良い（`sudo shutdown -h now`）。

1. `nerves_toolchain_ctng` を fork し、crosstool-NG 設定を
   **arm926ej-s / ARMv5TEJ / soft-float / glibc** で作成
2. ビルドした gcc で hello world をクロスコンパイル → Brainux 上で実行して検証
3. 同ツールチェーンで OTP 27 をクロスビルドできることを確認
4. 成功後、Phase 3（`nerves_system_br` ベースの Nerves rootfs 生成 →
   rootfs パーティション差し替え）へ

工数目安（提案書 §7）: Phase 2 = 2〜5日、Phase 3 = 1〜3週間。
