# 電源 ON/OFF・スタンバイ 調査報告(PW-SH6)

- 日付: 2026-09-04
- プロジェクト: hello_kiosk_brain(SHARP Brain PW-SH6 / i.MX283 / Linux 6.1.70)
- 目的: 電源 ON/OFF・スタンバイ(サスペンド)の実機挙動と実装可否の調査
- 方針: read-only 調査(実際の電源断/サスペンドは**未実行** — セッションが切れ、
  ウェイクできない恐れがあるため)

---

## 0. 要約

| 機能 | 可否 | 手段 | リスク |
|---|---|---|---|
| **電源 OFF** | △ **5V 未接続時のみ可** | `/sbin/poweroff` / 長押し。**USB/充電器接続中は不可** | — |
| **電源 ON** | ✕ ソフト不可 | 物理 PSWITCH(電源ボタン)のみ | — |
| **サスペンド(mem/deep)** | △ カーネルは対応・**未実績** | `echo mem > /sys/power/state` | **高**(ユーザー起床源が未登録=起きない恐れ) |
| **画面消灯(standby-lite)** | ◎ ソフトで即可能 | backlight brightness=0 | 無(SSH 維持・即復帰) |

> ### ★電源 OFF の実態(2026-09-04 実機で判明・要再検証)
> 1. **電源ボタン長押しでは切れない**(実機確認: **5V 無し=電池駆動でも**長押しで
>    電源が落ちない)。→ **i.MX28 に「長押し=自動ハード電源断」という機能は無い**
>    (このデバイスでは)。長押しは PSWITCH_IRQ をラッチするだけ。
>    ※ 旧版で「長押し=PMU ハード電源断」と書いたのは**誤り(未検証の思い込み)**。訂正。
> 2. **5V(USB VBUS / 充電器)給電中はソフト poweroff も切れない**。PMU が 5V で
>    生き続けるため(reboot=リセットは 5V でも効く)。**5V は PC の USB データ
>    ケーブルからも来る**ので、充電器と USB の**両方**を外さないと 5V は消えない。
> 3. **ソフト poweroff(`/sbin/poweroff` = syscon-poweroff)が電池駆動で実際に
>    電源を落とせるかは未検証**(検証時は常に 5V ありかオフラインだった)。
>    → 電池駆動での poweroff 動作確認が必要(下記 §検証課題)。
>
> **現状「確実に切れる」と言える方法は無い**(唯一確認できたのは電池切れ 0% での
> 自然停止)。電源ボタンを効かせるには、KIOSK が長押しを検出して poweroff を呼ぶ
> 実装が要る(短押し→確認画面は実装済み。長押し→poweroff は未実装)。
> ※ PC USB は給電のみで充電しない → 充電は純正充電器で。

### 検証結果(2026-09-04、USB=5V 接続下で実施)
KIOSK の電源系フローを実機で検証(すべて 5V 接続下=SSH 可能な状態):

| 項目 | 結果 |
|---|---|
| 電源ボタン(PSWITCH)短押し → 電源OFF確認画面 | **OK**(tick が PSWITCH_IRQ を検出→confirm_off) |
| ホーム「電源を切る」タップ → 確認画面 | **OK** |
| 確認画面「切る」を 5V 中にタップ → **USB案内画面**(usb_blocked) | **OK**(失敗ループ解消。前回の「ダイアログ再表示」バグは解決) |
| USB案内「戻る」 → ホーム | **OK** |
| 無操作 60 秒 → バックライト消灯 / タッチで復帰 | ~~OK(既検証)~~ **【訂正】実は消灯していない**(下記注) |

→ **5V 検出時に poweroff を試みず案内する**という設計は正しく動作。

### poweroff の実挙動(2026-09-04 実機確認)
- **`/sbin/poweroff` は非同期で即戻る**(数秒後に実際に作用)。戻り値で成否は判定不可。
- **USB/充電器接続(5V)中に「切る」→ 電源は切れず「再起動」になる**(実機確認:
  切る発火 → 約9秒 DOWN → 復帰、uptime リセット、正式構成で正常起動)。
  i.MX28 は 5V 給電中に PWD すると PMU が 5V で再起動するため。
- **電池駆動(5V 無し)では数秒後に電源が切れる**(ユーザー実機確認: 切る → 数秒後 OFF)。
- KIOSK は「切る」で `:powering_off` 画面「電源を切ります…」を出して poweroff を呼ぶだけ
  (旧「電源を切れませんでした」の失敗判定は poweroff 即戻りにより常時誤表示だったので廃止)。

### 未検証(電池駆動・物理操作が必要 = SSH 不可)
- **電池駆動(5V 完全に無し)で「電源を切る」→「切る」→ 本当に電源が切れるか**。
  (USB=5V を挿すと SSH できるが 5V で切れない。外すと SSH できない、の板挟み)
  → **ユーザーが実機を電池駆動のまま物理タッチして確認**するしかない。
  切れなければ `devmem 0x80044104 0x3E770001`(HW_POWER_RESET 直書き)を試す。
- 上記が通れば、電源ボタン**長押し検出 → poweroff** を KIOSK に実装する。

> **【追記 2026-09-05】** 「5V接続中の poweroff は再起動になる」件は追加調査で
> **シリコン仕様(5V存在中は電源断状態を維持できない)と確定**。純正の「USB中OFF」は
> サスペンドの可能性が高い。詳細:
> [20260905_電源OFF_5V接続中_調査結論.md](../adr/0005-電源OFF_5V接続中.md)

**結論**: 「画面消灯スリープ」はすぐ実用。**電源 OFF はソフト poweroff が唯一の
手段だが、電池駆動での動作が未検証**。長押しにハード電源断機能は無い。
サスペンド(suspend-to-RAM)はユーザー起床源が無く現状実用不可。

## 1. 電源 OFF(ソフト可能・確定)

- DTB: `power@80044000`(`syscon,simple-mfd`)配下に
  `poweroff`(`syscon-poweroff`)。
  - `reg` base = **0x80044000**(size 0x2000)= i.MX28 HW_POWER。
  - poweroff: **offset 0x104 / value 0x3E770001**。
    = `0x80044104`(HW_POWER_RESET)に **0x3E77_0001**(0x3E77=UNLOCK キー、bit0=PWD)を
    書くと SoC 電源断。
- ユーザーランド: `/sbin/poweroff` / `/sbin/halt` / `/sbin/reboot` すべて存在。
  カーネルが上記 syscon-poweroff を pm_power_off に登録するため、`poweroff` で電源断。
- **KIOSK 実装案**: 「電源 OFF」操作で `System.cmd("/sbin/poweroff", [])`
  (または devmem で 0x80044104 に 0x3E770001)。長押しキー/専用タブに割当可。

## 1.5 電源ボタン(PSWITCH)の押下はソフト検出可能(実機確認)

「電源」ボタンにキーコードが割り当たっていない理由と、検出可否を実機で調査した。

- **電源ボタンはキーボードマトリクス外**: GPIO キーボード(`sharp,brain-kbd-gpio`)の
  対応キーコードは 1-53 と 103-111(矢印/ナビ系)のみで、**KEY_POWER(116)を含まない**
  (`event0/capabilities/key` = `f780 0 33fffff fffffffe` を解析)。DTB にも
  gpio-keys / power-key / pswitch ノードは無い。→ **evdev のコードが付かないのは当然**。
- **実体は i.MX28 PSWITCH(HW_POWER 直結)**。押下は
  **HW_POWER_CTRL(0x80044000)の PSWITCH_IRQ(bit20)にラッチ**される(実機確認:
  bit20 を CLR で 0 → 電源ボタン短押し → bit20=1 に確定ラッチ、複数回再現)。
  - クリア: `HW_POWER_CTRL_CLR`(0x80044008)に `0x00100000` 書込。
  - 現状 **ENIRQ_PSWITCH(bit17)=0** = カーネル割込は無効。pswitch を扱う DT ノード/
    ドライバも無いため、**既定では短押しで何も起きない**(bit がラッチされるだけ)。
- **長押しでは電源が切れない**(実機確認: 5V 無し=電池駆動でも切れない)。
  → **i.MX28 に「長押し=自動ハード電源断」機能は無い**(このデバイス)。長押しは
  PSWITCH_IRQ をラッチするだけ。旧版の「PMU ハード電源断」記述は**誤り**、訂正。
  電源ボタンで切りたければ KIOSK が長押しを検出して poweroff を呼ぶ実装が必要。
- **→ ソフトで「電源ボタン」にアクションを割当可能**: KIOSK が PSWITCH_IRQ(bit20)を
  周期ポーリング(tick 毎に devmem read)し、1 を検出したら CLR でクリアして
  任意処理(例: 電源 OFF 確認画面を開く / スリープ復帰 / ホームへ)を実行できる。
  Battery が既に devmem を使うのと同じ経路。割込(ENIRQ)化はカーネル/DTB 作業。

## 2. 電源 ON(ソフト不可)

- i.MX28 は **PSWITCH(物理電源ボタン)**で PMU が起動 → ブートローダ → カーネル。
  **OFF 状態からソフトで ON にする手段は無い**(ブートローダ/ハード管轄)。
- PSWITCH は HW_POWER 内(CTRL 0x80044000 / STS 0x80044010 に状態・IRQ)。
  ※ 長押し(約 5 秒)で PMU レベルのハード電源断も可能(ソフト非依存)。
- 現状 CTRL=0x01518016 / STS=0x0403F113(参考値。PSWITCH 割込は未活用)。

## 3. サスペンド(suspend-to-RAM)— カーネル対応・未実績・起床源なし

- **カーネルは対応**: `/sys/power/state = freeze mem`、
  `/sys/power/mem_sleep = s2idle [deep]`(deep=suspend-to-RAM が既定)。
- **しかし未実績**: `/sys/power/suspend_stats/success = 0`(一度も成功していない)。
- **致命的: ユーザー起床源が無い**。登録済み wakeup ソースは **mmc0 / mmc1 のみ**。
  電源ボタン(PSWITCH)もキーボードも **wakeup 未登録**。
  → `echo mem > /sys/power/state` すると sleep には入るが、**ユーザー操作で起きられず
  電源再投入が必要**になる公算大。**リモート(SSH)で試すと復帰不能リスク**。
- 実用化には **PSWITCH かキーボード GPIO を wakeup source 化**(DTB の
  `wakeup-source` / `linux,wakeup` 付与 + ドライバ対応)が必要。カーネル/DTB 作業。
- **検証するなら物理アクセス下(電源ボタンで復帰できる前提)でのみ**。今回は未実行。

## 4. 画面消灯 standby-lite(ソフト即可能・推奨)

> **【訂正 2026-09-04 後刻】本節の「brightness=0 で LCD バックライト消灯」は
> 実機では効いていない。** sysfs/actual_brightness/PWM0 レジスタ(→pin100)までは
> 正しく変化するが、実機のバックライトは点灯したまま(目視確認)。backlight@0 は
> EVK 由来 DTB の宣言だけで実配線と不一致。したがって standby-lite の省電力効果は
> 現状無く、実制御線の特定(回路情報)が前提。詳細:
> [20260904_バックライト制御線_調査結論.md](../adr/0003-バックライト制御線_調査結論.md)

- backlight: `/sys/class/backlight/backlight@0/`(pwm-backlight)。
  - `brightness` = 0〜7(現在 7)、`bl_power`(0=on / 4=FB_BLANK_POWERDOWN)。
  - `brightness=0`(または `bl_power=4`)で **LCD バックライト消灯**。LCD は本機最大の
    消費源の一つで、点灯継続より確実に省電力。**システムは動作継続・SSH 維持・即復帰**。
- **KIOSK 実装案**: 無操作 N 秒でバックライト off(brightness 0)、タッチ/キーで復帰
  (brightness 7)。`Input` の既存イベントで起こせる。リスクゼロ。
- 注意: バックライトのみ off。fb0 の内容は保持(復帰で即表示)。CPU/BEAM は稼働継続
  なので消費は「フルスリープ」ほど下がらないが、KIOSK 用途には十分実用的。

## 5. 推奨ロードマップ

1. **即実装(低リスク)**: KIOSK に
   - 「画面消灯スリープ」(無操作タイムアウト → backlight 0、タッチ/キーで復帰)
   - 「電源 OFF」操作(`/sbin/poweroff`。誤操作防止に確認 UI)
2. **中期(要カーネル/DTB)**: suspend-to-RAM を実用化するなら、PSWITCH または
   キーボードを wakeup source 化。物理アクセス下で `echo mem` を検証してから。
   RTC 非搭載なので時刻復帰は別途 `settime.sh`。
3. 低電池時の自動 poweroff(Battery 監視 + `/sbin/poweroff`)も後日検討可。

## 6. 調査に使った確認(すべて read-only)

- `/sys/power/state` = `freeze mem` / `mem_sleep` = `s2idle [deep]` /
  `suspend_stats/success` = 0
- `/sys/class/wakeup/*/name` = mmc0, mmc1
- input: event0=brain-kbd-gpio, event1=mxs-lradc-ts, event2=pwm-beeper(電源キー専用は無し)
- DTB poweroff: base 0x80044000 / offset 0x104 / value 0x3E770001(syscon-poweroff)
- backlight@0: brightness 7/7, bl_power 0
- HW_POWER_CTRL=0x01518016, STS=0x0403F113(参考)
