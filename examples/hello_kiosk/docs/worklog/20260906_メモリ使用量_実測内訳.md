# メモリ使用量 実測内訳(PW-SH6 / 128MB 機)

> **Worklog**: この文書は作成時点の調査・作業記録です。現在の判断は [`../README.md`](../README.md) と [`../adr/`](../adr/) を優先してください。

- 日付: 2026-09-06
- プロジェクト: hello_kiosk_brain(SHARP Brain PW-SH6 / i.MX283 ARMv5 / 128MiB RAM / Linux 6.1.70)
- 目的: KIOSK ホーム画面の「メモリ」表示("使用量 / 総量 MB")の中身を実測で分解。
- 実機: 通常運用状態(KIOSK 稼働・有線LAN・起動直後)で計測。

---

## 1. 結論(サマリ)

**総RAM 112MB / 使用 約40MB / 空き 約72MB**。使用分の実体は**ほぼ単一の BEAM
プロセス(beam.smp、RSS 38MB)**。この Nerves システムは独立した OS サービスがほぼ
無く、erlinit が起動する 1 個の BEAM が全アプリ(Kiosk/Battery/Input/SshDaemon)を
担うため、「使用メモリ ≒ BEAM の RSS + カーネル数MB」になる。

- KIOSK 表示 "38 / 112 MB" の左は**使用量**(`MemTotal - MemAvailable`)、右は総 RAM
  (`MemTotal`)。詳細は [kiosk.ex `mem_used_mb`](../../lib/hello_kiosk_brain/kiosk.ex) の
  コメント参照。

## 2. 計測方法

- `:erlang.memory()` … BEAM 管理メモリの分解(total/processes/system/code/binary/ets/atom)
- `/proc/meminfo` … システム全体(MemTotal/MemAvailable/AnonPages/Cached/Slab 等)
- `/proc/self/statm` … beam.smp の実 RSS(2 番目のフィールド × 4KB)

## 3. 実測値(2026-09-06、有線LAN 192.168.222.57、起動直後)

### /proc/meminfo(抜粋、kB)
```
MemTotal:     115384   (≈112.7MB, KIOSK 表示の "112")
MemFree:       48352   (完全空き ≈47MB)
MemAvailable:  74116   (実質空き ≈72MB。回収可能キャッシュ込み)
Cached:        27424   (ページキャッシュ=ext4 rootfs。回収可能→"空き"扱い)
AnonPages:     26732   (匿名ページ=主に BEAM ヒープ)
Mapped:        12668   (mmap ファイル=NIF/共有lib/beam本体)
Slab:           5276   (うち SUnreclaim 3896 = カーネル非回収)
KernelStack:     504    PageTables: 216
```
→ 使用(`MemTotal - MemAvailable`)= 115384 - 74116 = **41268 kB ≈ 40MB**。

### :erlang.memory()(MB)
```
total: 23.3   processes: 8.9   system: 14.4
  code: 8.3   binary: 0.7   atom: 0.5   ets: 0.4
```
### beam.smp RSS
```
38876 kB ≈ 38MB  (KIOSK 表示 "38" にほぼ一致)
```

## 4. 使用 ~40MB の内訳

| 区分 | 実測 | 中身 |
|---|---|---|
| BEAM プロセスヒープ | 8.9 MB | Kiosk/Battery/Input/SshDaemon 等 全 Erlang プロセスの状態 |
| ロード済みコード(.beam) | 8.3 MB | OTP + アプリの BEAM モジュール(`code`) |
| mmap 済み(NIF+lib+beam本体) | ~12 MB | `kiosk_nif.so`(2.66MB, LovyanGFX+IPAフォント)+ 共有ライブラリ + beam 実行体(Mapped 12.4MB) |
| バイナリ/atom/ets/VM内部 | ~2.6 MB | 参照カウントバイナリ 0.7・atom 0.5・ets 0.4・その他 VM 内部 |
| カーネル非回収 | ~4.6 MB | Slab SUnreclaim 3.9 + KernelStack 0.5 + PageTables 0.2 |

- BEAM 管理合計は `:erlang.memory` の **23.3MB**。beam.smp の RSS 38MB との差(~15MB)は
  `:erlang.memory` に含まれない **mmap 分**(NIF・共有lib・beam 実行体)。
- 空き 72MB = 完全空き 47MB + 回収可能ページキャッシュ 27MB。

## 5. 所見

- 128MB 機で「アプリ全部込みの BEAM 38MB + カーネル数MB、残り約72MB 余裕」= **健全**。
- NIF を 44MB→2.66MB に縮小した効果(常時メモリ・dlopen I/O 削減)がここに効いている
  (詳細 docs/worklog/20260904_起動時タッチ遅延_調査.md §3-4)。
- **注意(2026-09-05 の教訓)**: この余裕は「瞬間的な大確保」には弱い。6MB の tar を
  `:erl_tar.extract` で BEAM 内展開したらメモリ逼迫で BEAM が落ちた。実機での重い in-VM
  処理(巨大バイナリの一括ロード等)は避け、ファイル操作は sftp かホスト側で行う。
- 正確な再計測は、実機オンライン時に §2 の 3 コマンドで随時取得可能。
