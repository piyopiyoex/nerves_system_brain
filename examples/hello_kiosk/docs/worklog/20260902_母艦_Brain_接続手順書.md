## 1. 構成概要

```
┌──────────────┐  USB (microUSB)   ┌──────────────────┐        ┌──────────┐
│ Brain PW-SH6 │◄─────────────────►│ 母艦 Linux        │◄──────►│ Internet │
│ Brainux      │  USB-NCM Gadget   │ enp0s20f0uX       │  NAT   │          │
│ usb0         │                   │ (cdc_ncm)         │        │          │
│ 10.42.0.2/24 │                   │ 10.42.0.1/24      │        │          │
└──────────────┘                   └──────────────────┘        └──────────┘
```

- Brain は WiFi/Ethernet 非搭載。ネットワークは **USB Ethernet Gadget (NCM)** の一本のみ
- IP アドレスは **「7」を含まない値**を採用（Brain キーボードの「7」キー入力不能バグ対策。
  SSH 確立後は母艦キーボードで作業するため影響なし）

## 2. 前提条件（初回のみ）

| 項目 | 内容 |
|---|---|
| Brainux イメージ | **2026-03-25 リリース系（USB NCM 対応）が必須**。旧イメージは `/sys/class/udc/` が空で USB ガジェット不動作 |
| ガジェット有効化 | Brain 側で **`sudo brain-config`** を実行し USB ガジェットを有効化（raspi-config 相当。初回のみ） |
| 起動方式 | 直接 SD ブート（`nk` ディレクトリの内容をブートパーティション直下へコピー済み。リセットだけで Brainux が起動） |
| USB ケーブル | **データ対応** microUSB ケーブル（充電専用は不可。判別方法は §7.1） |
| Brainux ログイン | ユーザー `user` / パスワード `brain` |

## 3. 接続手順（毎回）

現状の IP 設定は**揮発性**（Brain 再起動・ケーブル抜き差しで消える）。毎回以下を実行する。
恒久化する場合は §6 を参照。

### 3.1 物理接続と認識確認

1. Brain を直接 SD ブートで起動（リセット）
2. USB ケーブルで母艦と接続（**毎回同じ USB ポートを使う**とインターフェース名が安定する）
3. 母艦で認識確認:

```sh
ip a | grep -B2 -A3 'enp0s20f0u'
```

`enp0s20f0u1` のような `cdc_ncm` インターフェースが生えていれば OK
（末尾の数字は挿した USB ポートで変わる。以下 `enp0s20f0u1` と仮定し、実名に読み替える）。

認識しない場合は §7 トラブルシューティングへ。

### 3.2 母艦側: IP 設定

```sh
sudo ip addr add 10.42.0.1/24 dev enp0s20f0u1
```

### 3.3 Brain 側: IP 設定（Brain のコンソールで）

```sh
sudo ip addr add 10.42.0.2/24 dev usb0
```

※ このコマンドは「7」を含まないので Brain キーボードで入力可能。

### 3.4 疎通確認と SSH（母艦から）

```sh
ping -c 3 10.42.0.2
ssh user@10.42.0.2        # パスワード: brain
```

ログイン後のプロンプトは `user@brain:~$`。
**以後の Brain 側作業はすべてこの SSH セッション内で行う**
（プロンプトが `owner@localhost:~$` のままなら、それは母艦で実行している。§7.4 参照）。

実測値（2026-09-01）: RTT 約 2ms。

## 4. Brain をインターネットに出す（apt を使う場合のみ）

USB-NCM は母艦との 1対1 リンクなので、そのままでは Brain は外に出られない。
母艦を NAT ルータにする。

### 4.1 母艦側: NAT 有効化

```sh
sudo sysctl -w net.ipv4.ip_forward=1
sudo iptables -t nat -A POSTROUTING -s 10.42.0.0/24 -o enp0s31f6 -j MASQUERADE
```

- `-o` は**母艦が実際にインターネットへ出ているインターフェース**を指定
  （有線なら `enp0s31f6`、WiFi 経由なら `wlp0s20f3`。`ip route` の `default via` 行で確認）
- どちらも実行時のみ有効で、**母艦の再起動で自然に消える**（恒久変更ではない）

### 4.2 Brain 側: デフォルトルートと DNS（SSH セッション内で）

```sh
sudo ip route add default via 10.42.0.1
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
ping -c 3 8.8.8.8          # NAT 越しに外へ出られるか
ping -c 3 deb.debian.org   # DNS 解決込みで通るか
```

### 4.3 後始末（不要になったら・任意）

母艦の再起動でも消えるが、すぐ消したい場合:

```sh
sudo iptables -t nat -D POSTROUTING -s 10.42.0.0/24 -o enp0s31f6 -j MASQUERADE
sudo sysctl -w net.ipv4.ip_forward=0
```

## 5. クイックリファレンス（毎回の最短手順）

```sh
# ── 母艦 ──
sudo ip addr add 10.42.0.1/24 dev enp0s20f0u1     # 実インターフェース名に読み替え
# ── Brain コンソール ──
sudo ip addr add 10.42.0.2/24 dev usb0
# ── 母艦 ──
ssh user@10.42.0.2                                 # パスワード: brain

# apt が必要なときだけ追加:
# ── 母艦 ──
sudo sysctl -w net.ipv4.ip_forward=1
sudo iptables -t nat -A POSTROUTING -s 10.42.0.0/24 -o enp0s31f6 -j MASQUERADE
# ── Brain (SSH内) ──
sudo ip route add default via 10.42.0.1
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
```

## 6. 恒久化（毎回の手作業をなくす・任意）

### 6.1 母艦側（NetworkManager）

```sh
sudo nmcli con add type ethernet ifname enp0s20f0u1 con-name brain-usb \
  ipv4.method manual ipv4.addresses 10.42.0.1/24
```

- `ifname` ベースの指定のため、**同じ USB ポートに挿す運用**とセットで使う
- 実測では Brain 側 MAC は複数回の再起動をまたいで同一（`8a:15:8b:44:3a:01`）だったため、
  MAC ベースの紐付けも選択肢になり得る（個体・イメージ依存の可能性はあるので要観察）

### 6.2 Brain 側

`sudo brain-config` にネットワーク設定メニューがあればそれを優先。
なければ設定ファイルで固定する（`ls /etc/systemd/network/` で流儀を確認してから、
systemd-networkd なら `usb0` 用の `.network` ファイル、ifupdown なら
`/etc/network/interfaces` に static 設定を追加）。

## 7. トラブルシューティング（実機で遭遇した事象）

### 7.1 母艦の dmesg に何も出ない（USB 認識しない）

ケーブルか Brain 側ガジェットの問題。切り分け方法:

1. Brain を **WinCE（通常の電子辞書）モードで起動**して同じケーブルで接続
2. 母艦の `sudo dmesg -w` に `SHARP "Mass Dictionary"`（04dd:92e1、USB マスストレージ）が
   出れば**ケーブル・端子・母艦は正常** → 原因は Brainux 側（7.2 へ）
3. WinCE でも出なければ**充電専用ケーブル**の可能性大。データ対応ケーブルに交換

### 7.2 Brainux で `/sys/class/udc/` が空

カーネルが USB device モードを有効化していない = **イメージが NCM 対応前の旧版**。

- SD 先頭 FAT パーティションの `brainux_version` で版数確認
  （このファイル自体が無ければその時点で旧版と確定）
- [buildbrain releases](https://github.com/brain-hackers/buildbrain/releases) の最新イメージに
  書き直し → **直接 SD ブート用の `nk` ファイル再コピーを忘れずに** → `sudo brain-config` で
  ガジェット再有効化

### 7.3 インターフェースは生えるが ping が通らない

- 母艦・Brain 両側に IPv4 が付いているか確認（`ip a`）。**この設定は揮発性**で、
  Brain 再起動やケーブル抜き差しで消える → §3.2/3.3 を再実行
- 母艦のインターフェース名が変わっていないか（`enp0s20f0u1` ⇔ `u2` など。挿すポートで変わる）
- IPv6 リンクローカルで代替する場合は `ssh user@fe80::XXXX%enp0s20f0u1` の形式
  （`%インターフェース名` 必須）。ただし母艦側で当該インターフェースの IPv6 が
  無効だと `Network is unreachable` になる:
  `sudo sysctl -w net.ipv6.conf.enp0s20f0u1.disable_ipv6=0`

### 7.4 コマンドをどちらで実行しているか分からなくなった

プロンプトで判別する（実際に混同事故が起きたため明記）:

| プロンプト | 実行場所 | 備考 |
|---|---|---|
| `owner@localhost:~$` | 母艦 | EL 系なので `apt` は無い（`dnf`） |
| `user@brain:~$` | Brain (Brainux) | Debian なので `apt` |

Brain 用コマンドを母艦で実行してしまった場合は、母艦で `ip route`（`default via 10.42.0.1`
が紛れ込んでいないか）と `cat /etc/resolv.conf`（NetworkManager 生成のままか）を確認し、
不正な行があれば `sudo ip route del default via 10.42.0.1` / NetworkManager 再起動で復旧。

### 7.5 brain-config の設定が保存できない / 再起動で消える

- `brain-config` は設定を **`/boot/config.txt`** に書き込むが、`/boot` が読み取り専用
  マウントだと `Read-only file system` で保存に失敗する（実機で遭遇 2026-09-02）
- 対処: `sudo mount -o remount,rw /boot` → `sudo brain-config` で再設定 → 再起動
- USB ガジェットが再起動後に無効へ戻る症状は、この保存失敗が原因の可能性が高い

### 7.6 SSH 鍵認証の登録（初回のみ・推奨）

パスワード入力なしで SSH/scp できるようにする（自動化・エージェント作業の前提）:

```sh
# 母艦（公開鍵 ~/.ssh/id_rsa.pub が存在する前提）
ssh-copy-id user@10.42.0.2      # パスワード brain を1回入力
ssh user@10.42.0.2 hostname     # パスワードを聞かれなければ成功
```

### 7.7 Brain 本体のキーボードで「7」が入力できない（既知バグ）

- Brainux 上の既知問題（2026-09-01 実機確認）
- 対策: IP アドレス等、Brain 本体で直接入力する文字列には「7」を含む値を使わない
  （本書の 10.42.0.x はこの対策込みの採番）。SSH 確立後は母艦キーボードのため影響なし

## 8. Nerves SD で起動する場合（2026-09-02 更新・運用確立済み）

Nerves rootfs の SD（nerves_system_brain 製）では、ガジェットは erlinit の
`--pre-run-exec` で自動構成され、Brain 側 IP (10.42.0.2/24) も自動設定される。

### 8.1 前提（初回のみ）

- **p1 の imx28-pwsh6.dtb はデバイスモード有効化パッチ版であること**
  （配布イメージの DTB は `usb@80080000` が dr_mode="host" でガジェット不可。
  brain-config の「ガジェット有効化」の正体はこの DTB 書き換え。パッチ版は
  nerves_system_brain/sd/imx28-pwsh6-peripheral.dtb）
- 母艦側 IP は NetworkManager に恒久設定済み（`brain-usb` 接続、
  enp0s20f0u2 に 10.42.0.1/24 が自動付与）。手動の ip addr add は不要
- **ケーブルはデータ対応品を厳守**。過去の「列挙されない」事象の主因は
  充電専用ケーブルの取り違えだった。正しいケーブルなら**後挿しでも列挙される**
  （切り分けは §7.1 の WinCE マスストレージ法）

### 8.2 日常の使い方（母艦から）

```sh
ssh user@10.42.0.2                      # IEx ログイン（公開鍵認証、登録済み）
ssh user@10.42.0.2 'node()'             # 任意の Elixir 式をリモート評価（direct exec）
sftp user@10.42.0.2                     # ファイル転送（root=/ で全域アクセス可）
```

hello_kiosk_brain の開発サイクル（SD 往復不要）:

```sh
./scripts/build_release.sh              # リリース構築（OTP アプリ合流込み）
# → 変更 beam を sftp で /srv/erlang/lib/hello_kiosk_brain-*/ebin へ put
ssh user@10.42.0.2 ':code.purge(Mod); :code.load_file(Mod); GenServer.stop(HelloKioskBrain.Display)'
./scripts/screenshot.sh                 # 実機 LCD をリモートで PNG 取得
```

### 8.3 トラブル時

- 列挙されない → ケーブル確認（§7.1）→ ケーブル接続のまま Brain リセット
- LCD 右上が「NO IP」→ ガジェット構成失敗。LCD 起動ログの
  `enable_ethernet_gadget` 行を確認（診断は /root/gadget_diag.log にも保存される）
- Brainux SD と Nerves SD で母艦側の設定は共通（同じ 10.42.0.x 系）
