# バックライト制御線 調査結論 — sysfs backlight は実機に繋がっていない(調査打切り)

> **位置づけ**: この文書は調査・検証の詳細記録です。現在の判断は [`../adr/0003-バックライト制御線_調査結論.md`](../adr/0003-バックライト制御線_調査結論.md) を参照してください。

- 日付: 2026-09-04
- 発端: キー111 のバックライトトグルが「効かない」(引き継ぎ書 §0)
- 結論: **ソフトは全て正常。DTB の backlight 定義(PWM0/pin100)が実機の
  バックライト実配線と一致していない**(音声 SGTL5000@0x0a と同じ「EVK 由来
  DTB の宣言だけ」構図)。実制御線は未特定のため**調査打切り**(ユーザー判断)。

## 1. ソフト側は正常(全段確認済み)

- キー111 → Kiosk ハンドラは**物理押下で発火する**(診断マーカー
  `last_bl_toggle` が実押下で更新。KEYSタブに111が出ないのはハンドラ横取りの仕様)。
- `Backlight.off()/on()` → sysfs `brightness`/`actual_brightness` 反映 →
  **PWM0 レジスタまで正しく変化**(debugfs/devmem 実測):
  - brightness=7: ch0 有効、ACTIVE0=0x04b00000(duty100%、pin 常時 HIGH)
  - brightness=0: ACTIVE0=0、ch0 無効化(CTRL bit0 クリア)
- kiosk.ex は「brightness 0↔7 純粋トグル」に単純化済み(デバウンス・asleep 結合を除去、
  `Backlight.get/0` 追加)。**ハード制御線さえ見つかれば Backlight モジュール差替えだけで動く。**

## 2. 実機で目視テストした経路(すべて「画面変化なし」)

| テスト | 期待 | 結果 |
|---|---|---|
| brightness 0↔7 を1秒周期で10回点滅(sysfs) | 点滅 | 変化なし |
| ch0 無効化(devmem CTRL_CLR、HI-Z) | 消灯 | 変化なし |
| ch0 有効 + duty0 = **pin100(AUART1_RX/PWM_0)を LOW ハード駆動** | 消灯 | 変化なし |
| pin114(PWM2 パッド)GPIO HIGH 3秒 | 消灯 | 変化なし |
| pin101(AUART1_TX、DT の enable_gpios 先)GPIO LOW/HIGH | 消灯 | 変化なし |
| pin112(PWM0 物理パッド、現 i2c1 SCL)GPIO LOW/HIGH | 消灯 | 変化なし |

- devmem 書込み自体は有効(レジスタ読み戻しで全件確認)。テスト後すべて復元済み。

## 3. 判明した構成(記録)

- `backlight@0` = pwm-backlight, **ch0 → AUART1_RX パッド(pin100)**、
  `enable_gpios = <&gpio3 5>`(= pin101)は**プロパティ名 typo でドライバに無視**されている。
- `backlight@1` = ch2、`status="disabled"`。
- **PWM0/PWM1 物理パッド(pin112/113)は i2c1 に mux されている**(このバスの実在
  デバイスは未確認。音声調査の「実 I²C」と要突合)。pin114(PWM2 パッド)は未クレーム・
  GPIO OUT LOW。
- 過去の「devmem で ch0 無効化 → 画面真っ黒」(タッチ音調査時)は**統制再試験で再現せず**。
  誤帰属の疑い(bank3 は LCD 制御線を含むため、当時の別レジスタ操作が原因の可能性)。
  メモリ(buzzer-pwm4-pad-mux)は訂正済み。

## 3.5 【追試 2026-09-05】PW-SH6 固有 DTS の sharp,en-gpios を実機テスト → バックライト単独線は無い

外部資料(「PWM0+GPIO3_5 で8段階調光可能」)をきっかけに PW-SH6 **固有** DTS
(`linux-brain/arch/arm/boot/dts/imx28-pwsh6.dts`)を精査し、共通 dtsi の
backlight@0 とは別の真の制御線を発見・実機検証した。

### 発見: DRM パネルドライバの en-gpios
- `imx28-pwsh6.dts` は `&brainlcd`(`drivers/gpu/drm/tiny/brain.c`)に
  **`sharp,en-gpios = <&gpio0 26>, <&gpio0 27>, <&gpio4 16>`** を持つ。
- `brain.c` は probe で **この3本を GPIOD_OUT_HIGH で点灯**させ、以後保持
  (**輝度/PWM 制御コードは無い**。パネルは ILI9805 系で Sleep Out/Display On で制御)。
- 実機 debugfs: gpio-26 / gpio-27 / gpio-144(=GPIO4_16)が全て "out hi"、
  レジスタでも DOUT=DOE=1 で裏取り。

### 実機テスト結果(各 GPIO を単独で LOW 5秒 → 復帰、ユーザー目視)
| GPIO | devmem | 結果 |
|---|---|---|
| GPIO0_26 (DOUT0 bit26) | 0x80018708/704 | **画面真っ白**(復帰せず、再起動要) |
| GPIO0_27 (DOUT0 bit27) | 0x80018708/704 | **画面真っ白**(同上) |
| GPIO4_16 (DOUT4 bit16) | 0x80018748/744 | **画面真っ白**(同上) |

- 「真っ白」= **バックライトは点いたまま、LCD パネル制御(ILI9805 初期化)が壊れた**状態。
  GPIO を HIGH に戻すだけでは復帰せず(brain_enable 再実行が必要)、**再起動で復旧**。
- 3本とも LCD パネル電源/リセット系で、**バックライトだけを消す独立線は無い**。

### 確定結論
- **PW-SH6 のバックライトは、ソフトから独立に(安全に)制御できない。**
  バックライトは LCD パネル電源と一体で常時 ON。3本の en-gpios はどれも触ると
  パネルが破綻(白画面→要再起動)する。
- **PWM 調光(8段階)は不可**(backlight@0 は EVK 由来の非機能ノード、§2/§3 で実証済み)。
- 外部資料の「PWM0+GPIO3_5 で8段階制御可能」は共通 dtsi を読んだ理論のみで、
  **PW-SH6 実機では不成立**(資料は実機未検証)。
- 省電力で画面を落とすには、生 GPIO ではなく **DRM 正規の disable 経路
  (パネル Sleep In → 復帰時 Display On)** をカーネル/DRM 側で実装する必要がある
  (重い。当面は非対応)。

## 4. 含意

- **無操作スリープ(60秒で消灯)も実は消灯していなかった**可能性が高い
  (sysfs 値が変わるだけ)。省電力効果は要再評価。
- 実バックライト制御は LCD パネル側(SPI 初期化コマンド等)か別 GPIO の可能性。
  確定には回路図/teardown/brain-hackers 情報が必要 — 音声の 0x1a 同定と同じ壁。
- 再開する場合の入口: brain-hackers の PW-SH6 実機資料で backlight 配線を確認 →
  `Backlight` モジュールの書込み先だけ差し替え。
