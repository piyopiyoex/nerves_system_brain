# 電源OFF(5V/USB接続中)調査結論 — i.MX28 は 5V 存在中に電源断状態を維持できない

- 日付: 2026-09-05
- 発端: 「純正 Brain は USB ケーブルが繋がっていても電源ボタンで OFF できる。
  Nerves でもできないか」
- 結論: **真の電源断は不可能(シリコン仕様)。純正の「OFF」はサスペンド
  (RAM保持)の可能性が高い。** Nerves で同等をやるには「実バックライト制御」と
  「wakeup ソース」の2つが先に必要(いずれも既知の壁)。

## 1. 仕組みの確認(机上)

- Nerves/カーネルの poweroff は DTS の `syscon-poweroff`(imx28.dtsi):
  **HW_POWER_RESET_SET(0x80044104)に 0x3e770001(キー 0x3E77 + PWD)を書くだけ**。
- i.MX28 の電源投入トリガ候補: PSWITCH / 5V 検出 / RTC アラーム / AUTO_RESTART。
  ビット定義は U-Boot regs-power-mx28.h で確認。

## 2. 実機レジスタ(2026-09-05 実測)

```
HW_POWER_5VCTRL (0x80044010) = 0x04300115
  bit1 PWRUP_VBUS_CMPS = 0   ← VBUS検出の自動パワーアップは「既に無効」
  bit4 VBUSVALID_5VDETECT=1, VBUSVALID_TRSH=4.0V, PWD_CHARGE_4P2=0b11(充電4P2停止)
HW_RTC_PERSISTENT0 (0x80056060) = 0x00a00121
  bit17 AUTO_RESTART = 0     ← 電源断後の自動再始動も無効
  bit16 DISABLE_PSWITCH = 0(PSWITCH起動は有効)、ALARM 系 = 0
```
※ 昨日 PERSISTENT0 が読めなかったのはアドレス誤り(正: RTC=0x80056000、
PERSISTENT0=+0x60)。RTC ノードは DT で disabled だがレジスタは読める。

## 3. 決定実験(2026-09-05)

UI(:needs_unplug ガード)を迂回して USB 接続のまま `/sbin/poweroff`:
- t=14s でネットワーク断(電源断シーケンス完了)→ **t=21s で復帰(自動再起動)**。
- マスク可能なビット(PWRUP_VBUS_CMPS / AUTO_RESTART / ALARM)が全て無効でも
  再起動する = **「5V が存在する限り PMU がパワーアップする」レベルトリガのハード挙動**。
- 同系 PMU(iMX233)の既知挙動と一致: Rockbox FS#6465「充電中の idle poweroff が
  無限再起動ループになる」。死んだ電池でも USB を挿せば必ず boot ROM が走る
  (USB リカバリモードの前提)という設計の裏返しで、**封じる手段は無い**。

## 4. 純正ファームの「OFF」の正体(仮説・要確認)

- 純正 Brain は電源 ON で瞬時に前画面に戻る(WinCE のコールドブートでは説明困難)
  → **純正の電源OFF = サスペンド(RAM保持)** の可能性が高い。
- ユーザーへの確認事項: 純正機で「電源ON→瞬時に直前画面」か。
  (瞬時なら suspend 確定。数十秒かかるなら要再考。)

## 5. Nerves で純正相当(サスペンドOFF)をやる場合の前提条件

カーネルは suspend 対応あり(`/sys/power/state` = freeze/mem、mem は
mach-mxs/pm.c の WFI + デバイスサスペンド)。ただし現状:
1. **wakeup ソースがゼロ**: brain-kbd-gpio はポーリング式(wakeup 非対応)、
   PSWITCH のカーネルドライバ無し(アプリが devmem ポーリング)、RTC disabled。
   → 今サスペンドすると**電池切れまで起きられない**(実験も危険なので未実施)。
2. **バックライトを消せない**(20260904_バックライト制御線_調査結論.md)
   → サスペンドしても画面が光ったままで見た目が OFF にならない。

→ 必要なもの: ①実バックライト制御線の特定(回路情報)、
②PSWITCH(電源ボタン)を wakeup ソースにするカーネルドライバ。
どちらも「カーネル凍結・回路情報待ち」の既存の壁と同じ。

## 6. 方針の選択肢

1. **現状維持**(5V中は :needs_unplug 案内)← 当面の推奨
2. 擬似OFF: 5V中の「切る」→ 黒画面+最小動作、電源ボタンで復帰
   (バックライトが光ったままなので効果は限定的)
3. 本格対応: 回路情報入手後に「バックライト+PSWITCH wakeup+サスペンド」を
   カーネル込みで一括実装(音声 0x1a と同じ「実機HW確定」フェーズの課題)
