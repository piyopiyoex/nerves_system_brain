# タッチ音(PWM ブザー)調査 結論 — DT/pinmux は原因ではない

- 日付: 2026-09-04
- 対象: hello_kiosk_brain / nerves_system_brain / linux-brain(PW-SH6)
- 前提: [20260904_KIOSKデモ完成_タッチ音調査記録.md](../worklog/20260904_KIOSKデモ完成_タッチ音調査記録.md)
  (「ドライバ有効化まで成功、発音は未達。真因はカーネル層」まで到達していた)
- 結論: **DT/pinmux を実機レジスタで完全再現しても無音。原因は DT より下の層
  (ハード実配線 / コーデック)** と判明。DTB パッチによる解決は見込み薄。

---

## 1. 今回特定した pinmux の全体像

カーネル dtsi(`linux-brain/arch/arm/boot/dts/imx28-brain.dtsi`)に正式な
`buzzer_pins` グループが存在する:

```
buzzer_pins: pwm@2 {
    fsl,pinmux-ids = <
        MX28_PAD_PWM4__PWM_4              // PWM4 パッド(bank3 pin29)→ PWM_4 機能
        MX28_PAD_SAIF1_SDATA0__GPIO_3_26 // アンプ電源 GPIO パッド → GPIO_3_26
    >;
    fsl,drive-strength = <MXS_DRIVE_4mA>;
    fsl,voltage = <MXS_VOLTAGE_HIGH>;    // 3.3V
    fsl,pull-up = <MXS_PULL_DISABLE>;
};
```

**重要**: この `buzzer_pins` は dtsi に定義があるだけで **どのノードからも
参照されていない**(pwm ノードの pinctrl は `lcd_backlight_pins` のみ)。
= upstream の brain-hackers カーネルでもブザーの pin 配線は未完成で、
ブザーは元々 `status="disabled"`。だから今まで一度も鳴っていなかった。

### DTS のチャンネル対応(確定)
| ノード | PWM ch | パッド |
|---|---|---|
| backlight@0(LCD) | ch0 | AUART1_RX(bank3 pin4)→ PWM_0 |
| backlight@1(第2) | ch2 | — |
| buzzer(pwm-beeper) | ch4 | PWM4 パッド(bank3 pin29)→ PWM_4 |

※ ~~**PWM0/PWM2 はバックライト**。調査中に devmem で ch0 を無効化して
**画面が真っ黒**になった(再起動で復旧)。~~
**【訂正 2026-09-04 後刻】** 統制再試験(ch0 無効化 / ch0 有効+duty0 の LOW 駆動 /
pin100・101・112・114 の GPIO 直叩き)で**画面は一切変化せず、再現しなかった**。
backlight@0(ch0)も EVK 由来 DTB の宣言だけで実配線と不一致。当時の「真っ黒」は
別操作の誤帰属の疑い。詳細:
[20260904_バックライト制御線_調査結論.md](0003-バックライト制御線_調査結論.md)。
GPIO bank3 は LCD 制御線も含むため、PWM 検証で触るのは buzzer の pin26/pin29 に
限定する注意は引き続き有効。

## 2. レジスタ完全再現テスト(実機3回、すべて無音)

`buzzer_pins` 仕様を devmem で完全に再現した:

1. **PWM4 パッド**(bank3 pin29): MUXSEL7(0x80018170) bits26-27 を
   3(GPIO)→ 0(PWM_4)。DRIVE15(0x800183f0)の pin29 フィールドは
   **既に 0x4 = 4mA + 3.3V HIGH**(dtsi 指定と一致、変更不要)。
2. **アンプ電源 GPIO パッド**(SAIF1_SDATA0 = bank3 pin26): MUXSEL7 bits20-21 を
   0(SAIF1_SDATA0)→ 3(GPIO)。← これが従来 SAIF(音声)機能のままで、
   **レギュレータが GPIO3_26 を Low 駆動してもパッドに届いていなかった**。
3. **アンプ enable**: DOE3 bit26=1(出力)、DOUT3 bit26=0(Low)= active-low で ON。
   `buzzer_cold`(regulator-fixed, always-on)が駆動済み。
4. **PWM ch4 波形**: CTRL bit4=1、ACTIVE4=duty(50%)、PERIOD4=24000cyc@24MHz
   = 1kHz を正常生成(実測確認)。

→ **dtsi が指定する pin 設定・drive・voltage・アンプ enable・PWM 波形を
すべて満たした状態で、実機から発音せず**(1kHz を3秒、3パターンで検証)。

## 3. 結論と含意

- ブザー無音の原因は **DT/pinmux ではない**。したがって
  **DTB に `buzzer_pins` を張るパッチを当てても解決しない**(上記レジスタ
  再現と同じ状態を作るだけ)。SD 往復(物理)を伴う DTB 差し替えは見送る。
- 原因は **DT より下の層**と考えられる:
  1. PW-SH6 実機でブザーが PWM4 経路に物理配線されていない/未実装。
  2. アンプ/スピーカーが **SGTL5000 コーデック経由**(PWM 圧電ではなく音声
     コーデックの出力段)。SGTL5000 の MCLK 問題は別途未解決で、KIOSK の
     「オーディオ SGTL5000 = 準備中」表示もこれ。
  3. `buzzer_cold`(3.3V fixed-supply)がアンプ実電源に届いていない可能性。

## 4. 次アクション候補(本件は一旦保留)

- **SGTL5000 音声パスの確立**を先に行う(MCLK 供給 + ALSA)。ブザー音も
  実はこの経路の可能性がある。KIOSK オーディオ全体として着手する方が効率的。
- ハード実配線の確認(回路図 / brain-hackers の情報)。PWM4 パッドに実際に
  ブザーが繋がっているかを確定する。
- どちらも「カーネル/コーデック」系のまとまった作業。単発の pinmux では解決せず。

## 5. 検証で使ったレジスタ(記録)

- MUXSEL7: `0x80018170`(SET `+4`=0x174 / CLR `+8`=0x178)。復元は
  `devmem 0x80018170 0x1fc00035` を直接書き戻す。
- DRIVE15: `0x800183f0`(pin29 = bits20-23、値 0x4 = 4mA/3.3V)。
- GPIO3: DOUT `0x80018730` / DOE `0x80018b30`(bit26 = アンプ enable)。
- PWM: CTRL `0x80064000`、ACTIVE_N `0x80064010+N*0x20`、PERIOD_N `0x80064020+N*0x20`。

## 6. 追試(2026-09-05): pwm-beeper ドライバ正規経路でも無音を確認

§2 の「レジスタ直叩き」に対し、**pwm-beeper ドライバの input デバイス経由**(正規の
鳴らし方)でも試して、駆動側が本当に動いているかまで詰めた。結論は**完全無音**で、
**無音の原因は SoC ピンより下流のハード/回路にあると確定**した(ソフトの不足ではない)。

### 前提: DTB/ドライバは有効化済み・bind 済み
- 現行 Nerves DTB は `buzzer`(pwm-beeper, PWM4, amp-supply=buzzer_cold)/`buzzer_cold`
  (regulator-fixed, GPIO3_26 active-low, always-on)/`pwm@80064000` を**すべて
  `status="okay"`** に設定済み。`CONFIG_INPUT_PWM_BEEPER=y`。
- 実機 dmesg: `input: pwm-beeper as /devices/soc0/buzzer/input/input2`。
  `/proc/bus/input/devices` に `Name="pwm-beeper"` / `Handlers=... event2` /
  `EV=40001`(EV_SND)/ `SND=6`(SND_BELL+SND_TONE)。**ドライバは正常 bind、
  input デバイス /dev/input/event2 が生成されている。**

### 実施: evdev で SND_TONE / SND_BELL を送出
`/dev/input/event2` へ input_event(EV_SND=18, SND_TONE=2 / SND_BELL=1)を書込。
500/1000/2000/3000/1500Hz の各 0.5 秒 + SND_BELL×3 を約6秒間送出 → **実機で完全無音**
(ユーザー実聴)。

### 決定的証拠: トーン中に PWM4 は実際に波形を出している
2000Hz トーンを鳴らしたまま PWM/GPIO レジスタをライブ読取り:
```
PWM CTRL(0x80064000): 0x3fc00001(停止時)→ 0x3fc00011(鳴動中、bit4=PWM4 enable ON)→ 0x3fc00001(停止後)
PWM4 ACTIVE(0x80064090): 0x17700000   PWM4 PERIOD(0x800640a0): 0x000b2ee0(波形パラメータ設定済み)
アンプ enable GPIO3_26: DOUT bit26=0(Low)/ DOE bit26=1(出力)= active-low で ON
```
→ **ドライバ→PWM4 enable→波形生成→アンプ enable の Linux 側連鎖はすべて正しく動作**
しているのに音が出ない。

### 帰結
- §2(レジスタ直叩き)と §6(ドライバ正規経路)の**両方で無音**。Linux から到達できる
  範囲(pinmux/PWM波形/アンプ enable GPIO)は完全に正しい。→ **無音は DT/ソフトでは
  なく、SoC ピンより下流の実基板配線**(EVK 由来 DTS と PW-SH6 実機の不一致。0x0a
  コーデック不在・0x1a 未同定と同根)。
- 電源/リセット時の「ピピ」は**本体ファーム(EC)**が鳴らすもので、Linux が触れる
  PWM4/GPIO3_26 とは別経路(スピーカー自体は存在するが、Linux 側の到達経路が塞がっている)。
- **オンボードブザーでのタッチ音は回路情報(実配線・アンプ電源・codec 経由か否か)
  無しには突破不能**と再確定。→ タッチ音の現実解は **USB オーディオ**(USBホスト化済・
  `CONFIG_SND_USB_AUDIO=y`)。UAC ドングルをハブに挿し、タッチ契機で短いクリックを再生する。
