# 0004: SGTL5000 を PW-SH6 のオンボード音声として扱わない

## 状態

採用（0006 で音声経路の方針を補完）

## 背景

稼働 Device Tree は `sgtl5000@0x0a` を宣言しているが、PW-SH6 実機では音声デバイスが
probe せず、MCLK や probe 順序の問題も疑われていた。

## 決定

PW-SH6 のオンボード音声について、現行 DTB の SGTL5000 定義を正しいハードウェア記述と
みなさない。0x1a の実デバイスを特定できるまで、SGTL5000 前提のカーネル/DTB 修正は進めない。

## 理由

- 実機 I2C bus では DTB が宣言する 0x0a / 0x28 / 0x48 が NAK し、未宣言の 0x1a / 0x50 が ACK した。
- MCLK を正規シーケンスで有効化しても 0x0a は NAK のままで、SGTL5000 自体が不在と判断できる。
- 0x1a はコーデックらしい応答を示すが、型番をソフトウェアだけで確定できていない。

## 影響

- `sgtl5000` の probe エラーを直すためだけの MCLK/driver 修正は行わない。
- オンボード音声の復旧には、回路図・基板目視・ロジック解析など別の根拠が必要になる。
- 現在の音声方針は ADR 0006 の USB オーディオを優先する。

## 再評価条件

0x1a の型番と配線が確定し、PW-SH6 用の正しい audio Device Tree を構成できる情報が得られた場合に再評価する。
