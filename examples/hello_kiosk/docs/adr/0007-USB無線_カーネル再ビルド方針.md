# USB 無線(WiFi/BLE)ドングル調査 と カーネル再ビルド方針(B案)

- 日付: 2026-09-06
- プロジェクト: hello_kiosk_brain(SHARP Brain PW-SH6 / i.MX283 ARMv5 / Linux 6.1.70)
- 目的: USB ホスト化(有線LAN で実績済み)の上に **WiFi** と **BLE**(SwitchBot 温湿度
  センサー取得)を載せる。到着した各ドングルを実機で検証し、最終方針を決定。
- 前提: USB ホスト + セルフパワーHub は動作確認済(有線LAN eth0 で稼働、[別記録](../worklog/20260905_有線LAN化_USBホスト_実施記録.md))。

---

## 1. 結論

**現行 6.1 カーネルのままでは、手持ちの WiFi ドングルは 2 種とも動かず、BLE は不可**。
到達した最終方針は **B案 = カーネル再ビルド**。1 回の再ビルドで次を同時に開通できる:
- **ath9k(AR9271)の endpoint 検査を緩める** → ONKYO UWF-1(手持ち)で WiFi
- **`CONFIG_BT` + `CONFIG_BT_HCIBTUSB` 追加** → BLE(SwitchBot 直接取得)
- (任意)rtw88 USB バックポート → RTL8811CU の 11ac(移植が重いので後回し)

## 2. 検証したドングルと結果(実機)

### (a) TOKAIZ TWA-001 / B08WJ595WR = Realtek RTL8811CU(`0bda:c811`)
- USB 認識するが**ドライバ未バインド・wlan0 出ず**。
- 原因: カーネルは `RTW88=y`(コアのみ)で **rtw88 USB サブドライバ(rtw8821cu)が未組込**。
  rtl8xxxu は 802.11n 専用でこの 11ac チップを掴めない。
- linux ソースでも rtw88 の USB 対応(rtw88_usb/rtw8821c/8811cu)は **6.2 以降で mainline 化**。
  この 6.1 ツリーには無く、**バックポートが必要**(移植で難、費用対効果低)。

### (b) Atheros AR9271 変種「UB93」→ 実体は ONKYO UWF-1(`0cf3:9271`)
- USB 認識・`ath9k_htc` は反応するが **`Device endpoint numbers are not the expected ones`**
  で拒否(firmware ロードの手前)。**wlan0 出ず**。
- 原因: **5.15+ で追加された endpoint 検査**(Fedor Pchelkin, Syzkaller 由来)が、REG_OUT を
  **interrupt** エンドポイントとして要求。UWF-1(AR9271)の実測エンドポイントは
  `0x01/0x04/0x05/0x06=Bulk、0x82=Bulk IN、0x83=Interrupt IN`(**interrupt OUT が無い**)ため
  `usb_find_common_endpoints` が失敗し `-ENODEV`。**同一 0cf3:9271 の TL-WN722N でも Debian で
  同じ拒否が報告**([Debian報告](https://groups.google.com/g/linux.debian.user/c/Rh3EE0u7yKo) /
  [パッチ経緯](http://linuxtesting.org/pipermail/lvc-project/2022-October/000065.html))=
  **カーネルの過剰検査による既知回帰**で、UWF-1 自体は良チップ(完全オープン・Linux 実績豊富)。
- 補足: 実機に **`/lib/firmware` が丸ごと無かった**ため、`htc_9271.fw`(50980B)を
  `/lib/firmware/htc_9271.fw` と `/lib/firmware/ath9k_htc/htc_9271-1.4.0.fw` に配置済み(母艦
  linux-firmware の `htc_9271.fw.xz` を展開。versioned .xz は母艦側が破損していたので
  unversioned から複製)。**検査さえ通れば効く**下地は完成。

## 3. カーネルの無線・BT 対応状況(実機 /proc/config.gz)

- WiFi スタック: `CFG80211=y / MAC80211=y / WLAN=y`。
- USB WiFi ドライバ(=y): MediaTek `MT7601U/MT76x0U/MT76x2U/MT7663U/MT7921U`、Realtek
  `RTL8XXXU`(11n)/`RTL8187`、Ralink `RT2800USB`、Atheros `ath9k_htc`。
- **Bluetooth: 完全に非対応**(`CONFIG_BT`/`BLUETOOTH`/`BTUSB` の実エントリがゼロ。"HCI" は
  EHCI/OHCI の誤ヒットのみ)。→ **BLE はどのドングルでも現状不可、カーネルに BT スタックが要る**。
- 注意: 手元 `linux-brain` は **5.4.149**、実機は **6.1.70-ga9f534c7f53e**(別ソース)。
  再ビルドには brain-hackers の **6.1 系ソース**が必要。

## 4. SwitchBot(BLE)取得の位置づけ

- 参照実装 `nerves_examples/hello_scenic_7inch`(RPi3)は **BLE パッシブスキャンを HCI-over-UART**
  (`Circuits.UART` で HCI を直接、RPi オンボード BT が UART 接続)。SwitchBot 広告
  `Service Data 0xFD3D / Manufacturer 0x0969` から温湿度をデコード。**この解析ロジックは移植で再利用可**。
- Brain は BT が無いので、直接 BLE には **①BT スタック(CONFIG_BT+btusb)②USB BT ドングル
  ③トランスポートを UART→USB-HCI(BlueZ or 生 hci0)に改修** が要る。
- 代替(BLE を Brain に載せない): (A) RPi3 が読み Brain は network 経由で表示、(B) SwitchBot
  Cloud API(要 Hub)。→ 別途検討可だが、今回は **B案(BLE を Brain に載せる)方針**を採用。

## 5. 採用方針 = B案(カーネル再ビルド)

**目的**: 1 回の再ビルドで「UWF-1 の WiFi」+「BLE」を開通。

**やること(想定)**:
1. brain-hackers **6.1 系カーネルソース**取得(実機の `-ga9f534c7f53e` に対応する branch/commit)。
2. ARMv5(arm926t)クロスツールチェーン用意(nerves_system_brain の Bootlin toolchain 流用検討)。
3. **パッチ/config**:
   - ath9k `hif_usb.c` の endpoint 検査を緩める(REG_OUT が bulk の AR9271 を通す小パッチ)。
   - `CONFIG_BT=y`, `CONFIG_BT_HCIBTUSB=y`(+ `BT_HCIBTUSB_RTL` 等), `CONFIG_BT_LE` 相当。
   - (任意)rtw88 USB は今回スコープ外(重い)。
4. **firmware**: ath9k_htc(配置済)+ BT ドングルの firmware を /lib/firmware に。
5. `zImage` ビルド → SD の p1(FAT boot)へ配置(物理 SD 往復。zImage 差替)。
6. 実機で UWF-1 → wlan0、BT ドングル → hci0 を確認。

**リスク/未確定**: 6.1 ソースの入手性、config の再現(実機 config.gz を base に)、モノリシック
方針(モジュール不可=すべて =y)。ビルドは時間がかかる。
