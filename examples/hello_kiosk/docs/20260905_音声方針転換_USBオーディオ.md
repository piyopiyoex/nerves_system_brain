# 音声方針転換 — オンボード SGTL5000 を凍結し USB オーディオを本命に

- 日付: 2026-09-05
- プロジェクト: hello_kiosk_brain(SHARP Brain PW-SH6 / i.MX28)
- 結論: **PW-SH6 の音声はオンボードコーデック(SGTL5000/0x1a)経由では回路情報の壁で
  行き止まり。実機カーネルに USB オーディオが既に組込済みのため、音声の土台を
  USB オーディオに切り替える。** 前提は USB ホスト有線 LAN と共通で、予備機の
  Phase 0 と一体で進める。
- 前提資料: [20260904_音声調査結論_DTBと実機I2C不一致.md](20260904_音声調査結論_DTBと実機I2C不一致.md) /
  [20260904_音声0x1aコーデック同定_作業報告兼質問書.md](20260904_音声0x1aコーデック同定_作業報告兼質問書.md) /
  [20260904_バックライト制御線_調査結論.md](20260904_バックライト制御線_調査結論.md)(EVK boilerplate の同型パターン)

## 1. オンボード音声が行き止まりである根拠(実機再確認 2026-09-05)

### 1.1 実機 ALSA は立ち上がっていない
```
sgtl5000 0-000a: Error reading chip id -6     ← 0x0a に応答なし(NAK)
No soundcards found.
platform sound: deferred probe pending          ← 来ないコーデックを待ち続ける
/proc/asound/cards → --- no soundcards ---
```

### 1.2 共通 dtsi の音声定義は i.MX28 EVK のコピー(boilerplate)
`linux-brain/arch/arm/boot/dts/imx28-brain.dtsi`:
```
sound {
    compatible = "fsl,imx28-evk-sgtl5000", "fsl,mxs-audio-sgtl5000";
    model = "imx28-evk-sgtl5000";     ← Freescale EVK リファレンス基板そのまま
    audio-codec = <&sgtl5000>;        ← codec@a (0x0a) も EVK 由来
};
```
- PW-SH6 固有 `imx28-pwsh6.dts` は **LCD(brainlcd)とキーボードは実機仕様に上書きするが、
  音声は一切上書きしない**。= 誰も PW-SH6 実音声ハードに合わせていない。
- バックライト調査で判明した「共通 dtsi は EVK boilerplate で実機と不一致」と**同型**。
- ∴ **PW-SH6 で Linux 音声が鳴った実績はまず無い**(以前の推測が裏付けられた)。

### 1.3 0x1a の同定はソフトだけでは限界
- 0x1a は read に構造的応答を返すが read プロトコルが不整合で真のレジスタ値を断定できず、
  NAU8822 の DEVICE_ID も出ない(2026-09-04 実機、否定寄り)。
- 確定にはロジックアナライザか回路図が必要 = バックライト実配線・電源系と**同じ壁**。
- 外部資料の「まず 0x1a を同定せよ」は既に到達済みの行き止まりで、再挑戦は低効率。

## 2. USB オーディオが本命である根拠

### 2.1 実機カーネルに既に組込済み(/proc/config.gz、2026-09-05 確認)
```
CONFIG_SND_USB_AUDIO=y          ← USB オーディオクラス
CONFIG_SND_USB=y
CONFIG_USB_CHIPIDEA_HOST=y      ← USB ホストモード
CONFIG_USB_EHCI_HCD=y
CONFIG_USB_STORAGE=y            ← ついでに USB メモリも
現在の USB ロール: ci_hdrc.0(今は gadget = USB-NCM)
```
- nerves_system_brain は独自カーネルを持たず **Brainux(brain-hackers linux-brain)の
  zImage/DTB を流用**。その実カーネルに上記が入っている。
- **USB オーディオはカーネル再ビルド不要**(USB-Ethernet はドライバ追加=再ビルド必須
  だったのと対照的)。

### 2.2 利点
- **コーデック同定不要**: USB オーディオは標準クラスドライバ。0x1a の壁を丸ごと迂回。
- **前提が USB ホスト有線 LAN と完全共通**: dr_mode=host + VBUS(セルフパワー Hub)。
  → [20260903_有線LAN化_USBホスト_提案書.md](20260903_有線LAN化_USBホスト_提案書.md) の Phase 0 と一体。
- **相乗効果**: ホスト + セルフパワー Hub なら USB-Ethernet(開発アクセス+LAN)と
  USB オーディオを同時接続でき、1つの Hub で「LAN + 音声 + 給電」が揃う。

## 3. 実装の道筋(予備機到着後)

1. **Phase 0(共通の関門)**: microUSB が USB host + VBUS 給電を通すか(既知の未確認点)。
   通れば以下は素直。ダメなら USB 経路全体が不成立。
2. USB オーディオドングル(UAC1/UAC2 標準クラス)を挿す → `/proc/asound/cards` に出現。
3. **8kHz/mono/16bit WAV から再生テスト**(外部資料の切り分け手順は USB でも有効)。
   - `aplay`(alsa-utils)は現状 Nerves 未収録の可能性 → buildroot に `alsa-utils` を
     追加(軽量な system 再ビルド)、または Elixir から `/dev/snd/pcmC*D*p` に PCM 直書き。
4. hello_kiosk_papapa の音声素材(priv/audio/notes)を PW-SH6 の内蔵/イヤホン出力へ。
   ※ PW-SH6 の音声出力は仕様上モノラル。

## 4. 方針まとめ

| 経路 | 状態 | 判断 |
|---|---|---|
| オンボード SGTL5000(0x0a) | 実機に不在(EVK boilerplate) | 不可 |
| オンボード実コーデック(0x1a) | 同定不能(要ロジアナ/回路図) | 回路情報が来るまで凍結 |
| PWM ブザー(PWM4) | pinmux 完全再現でも無音(別途調査済) | 凍結 |
| **USB オーディオ** | **カーネルに組込済(=y)** | **本命。USB ホスト化と一体で実装** |

- オンボード音声は回路情報(brain-hackers / teardown / 基板目視での 0x1a 型番確認)が
  入手できるまで**凍結**。
- 音声の主経路は **USB オーディオ**。予備機の USB ホスト有線 LAN(Phase 0)と同時に進める。
